## §1 节点边界 + L0 红线回引

### 1.1 In-scope(本设计锁定)

- Volcengine SAUC bigmodel 实时语音识别 endpoint(`wss://openspeech.bytedance.com/api/v3/sauc/bigmodel`)二进制 WebSocket 帧协议(4-byte custom header + JSON / PCM payload + gzip flag bit)的 Swift 端打包/解包路径
- 4 个鉴权 header(`X-Api-App-Key` / `X-Api-Access-Key` / `X-Api-Resource-Id` / `X-Api-Connect-Id`)从 Keychain `volc-asr-credentials` 读取 → URLRequest 注入 → ARC 释放的密钥生命周期序列图
- 首帧 `full-client-request`(message type = `0x1`)JSON payload schema:`audio.{format/rate/channels/codec}` + `request.{model_name/enable_itn/enable_punc}`
- 后续音频帧(message type = `0x2`,即 `client-audio-only-request`)PCM 6400 bytes payload 推流逻辑(对接 M2.6 AudioCaptureService 的 `onPCMChunk` 回调,**Swift 内部直注入,不经 JS**)
- 接收响应帧(message type = `0x9`,即 `server-full-response`)解析:`result.utterances[].definite` boolean 决定 partial / final
- BridgeEvent 推送形态:`asr-partial` / `asr-final` / `asr-end`(BridgeEventSchema 已含,M2.4 落地;**本节点不扩 enum**,只补 payload Zod schemas)
- Bridge method 增量:`asr.start` / `asr.stop` / `asr.status` 3 条
- WebSocket close code 处理:`1000` 正常关闭、`1011` server overload(限流)指数退避重连 ×3、`1006`/URLError 网络中断重连 ×3、鉴权失败显式抛 `asr.api-key-invalid`
- 13 条 `asr.*` BridgeError 错误码 starter codebook
- M2.8.dev 5-way split implementation roadmap(.a frame Codable / .b WS connect + auth / .c receive loop + dispatch / .d audio bind + lifecycle / .e JS iterator + smoke)
- 测试矩阵(XCTest + Vitest + 双端 round-trip + 真调 SAUC manual checklist)

### 1.2 Out-of-scope(留给后续节点)

- M3.4 — UI 端流式消费 hook(`useASRStream` / 面试 turn 显示组件)
- M2.9 — TTS Gateway(火山 TTS 流式合成,与本节点同样走 `openspeech.bytedance.com`,但是另一条 path)

## §2 SAUC endpoint + ATS / 网络白名单

### 2.1 Endpoint 与连接形态

火山引擎 SAUC bigmodel 实时语音识别(WebSocket 二进制协议):

```
wss://openspeech.bytedance.com/api/v3/sauc/bigmodel

WebSocket Upgrade 时携带 4 个鉴权 header:
  X-Api-App-Key:     <appId>           // 来自 Keychain volc-asr-credentials
  X-Api-Access-Key:  <accessToken>     // 来自 Keychain volc-asr-credentials  ← secret
  X-Api-Resource-Id: volc.bigasr.sauc.duration
  X-Api-Connect-Id:  <UUID per connection>

Subprotocol: 无;协议体走二进制帧(Data frames)。
```

> **决策(标注:推断 — 待 M2.8.dev.a WebFetch 校验)**:
> - `X-Api-Resource-Id` 的 value 字符串 `"volc.bigasr.sauc.duration"` 来自社区文章与火山官方网关命名约定推断
> - 4 个 header 字段名按 Volcengine OpenAPI 通行 `X-Api-*` 前缀推断
> - `X-Api-Connect-Id` 是每次 WS 连接随机生成的 UUID(便于火山日志侧追踪)
> - **任何不一致**:M2.8.dev.a 第一个 step 是 `WebFetch https://www.volcengine.com/docs/6561/1354869`(及候选 URL 列见 §13);拿到 official spec 后若与本 doc 不一致,developer 必须停下报告,architect 下一 loop 修订本 doc(**不**自行硬编码)

### 2.3 决策:URLSession 层冗余 hostname check —— **必须冗余**

ATS 已经在系统层拦截非白名单 host,但 ASRGateway 在 Swift 代码层 **再做一次 hostname 白名单 check**,理由完全平行 LLMGateway §A0.3 决策:

1. **Defense-in-depth**:多层防御原则;ATS 防 TLS 握手,代码层防 URL 构造期的字符串注入(如未来某 PR 把 `endpoint` 改成可配置变量被错误参数赋值)
2. **错误码语义更准确**:ATS 失败抛 `NSURLError -1003 / -1004`,代码层显式 check 抛 `asr.host-not-allowed`,与其他 `asr.*` 错误码体系一致
3. **测试可控**:XCTest 用 URLProtocol mock(虽然 URLSessionWebSocketTask 的 mock 路径与 URLSession.dataTask 略有差异,§10.1 详述)只有代码层 check 能在 mock 下覆盖
4. **commit history 防御**:复制粘贴 host 字符串时引入空格 / 大小写差异,代码层 lower-case 对比可早早抛错

**实施位置**:`ASRGateway.connect(...)` 入口处:

```swift
private static let allowedHost = "openspeech.bytedance.com"
private static let endpoint = "wss://openspeech.bytedance.com/api/v3/sauc/bigmodel"

private func makeWebSocketRequest(creds: VolcAsrCreds, connectId: String) throws -> URLRequest {
    let url = URL(string: Self.endpoint)!
    guard url.host?.lowercased() == Self.allowedHost else {
        throw BridgeError(code: "asr.host-not-allowed",
                          message: "host '\(url.host ?? "")' not in allow list")
    }
    var req = URLRequest(url: url)
    req.setValue(creds.appId, forHTTPHeaderField: "X-Api-App-Key")
    req.setValue(creds.accessToken, forHTTPHeaderField: "X-Api-Access-Key")
    req.setValue("volc.bigasr.sauc.duration", forHTTPHeaderField: "X-Api-Resource-Id")
    req.setValue(connectId, forHTTPHeaderField: "X-Api-Connect-Id")
    // creds.accessToken goes out of scope at function return → ARC release
    return req
}
```

## §3 4 个 Auth Header + accessToken 生命周期

### 3.1 生命周期序列图(ASCII)

```
+-----------+   1. read("volc-asr-credentials")   +----------+
|ASRGateway | ----------------------------------> | Keychain |     # Swift in-process,never crosses Bridge
| .connect()| <---------------------------------- | Service  |
+-----------+   2. Data? (utf8 JSON bytes)        +----------+
      |
      | 3. let creds = try JSONDecoder().decode(VolcAsrCreds.self, from: data)  # stack-local
      |    guard !creds.appId.isEmpty && !creds.accessToken.isEmpty
      v
+-----------+   4. URLRequest.setValue(creds.appId,        forHTTPHeaderField: "X-Api-App-Key")
| URLRequest|      URLRequest.setValue(creds.accessToken,  forHTTPHeaderField: "X-Api-Access-Key")  ← secret 唯一驻留点
+-----------+      URLRequest.setValue("volc.bigasr.sauc.duration", forHTTPHeaderField: "X-Api-Resource-Id")
      |            URLRequest.setValue(UUID().uuidString,  forHTTPHeaderField: "X-Api-Connect-Id")
      |
      | 5. URLSession.shared.webSocketTask(with: request).resume()
      |    # TLS handshake → ATS check → WS Upgrade → 4 headers 跨 TCP 边界
      v
+-----------+   6. WebSocket frames bidi
|  Volc     |
|  SAUC     |
+-----------+
      |
      | 7. function returns / connection closes
      |    Swift ARC drops `creds` struct, URLRequest, URLSessionWebSocketTask
      v
+--------------------------------------+
| ARC release: zero secret in memory   |
+--------------------------------------+

Throughout: NEVER log accessToken, NEVER write to file, NEVER cross Bridge boundary,
            NEVER store on instance property, NEVER pass in PCM payload.
```

**关键不变量**:

- `VolcAsrCreds` struct 必须是 **stack-local**(在 `connect()` 函数局部变量,函数返回即释放);**绝不**写入 instance property、static、UserDefaults、SQLite、log
- `URLRequest.allHTTPHeaderFields` 字典在 URLSessionWebSocketTask 持有期间存活;task `cancel()` 后随 ARC 释放
- 每次新建 WS 连接(包括重连)都重读 Keychain,**不**缓存 `VolcAsrCreds` 跨连接(Keychain `SecItemCopyMatching` ~1ms / call,可忽略)
- 重连时每次重新生成 `X-Api-Connect-Id` UUID(便于火山服务端日志区分重连事件)

### 3.2 调用点伪代码(供 M2.8.dev.b 直接抄)

```swift
final class ASRGateway {
    private let keychain: KeychainService
    private static let endpoint = "wss://openspeech.bytedance.com/api/v3/sauc/bigmodel"
    private static let allowedHost = "openspeech.bytedance.com"
    private static let resourceId = "volc.bigasr.sauc.duration"

    private var task: URLSessionWebSocketTask?
    private var connectId: String = ""
    private var streamId: String?
    private weak var router: BridgeRouter?

    init(keychain: KeychainService, router: BridgeRouter) {
        self.keychain = keychain
        self.router = router
    }

    /// Build URLRequest with 4 auth headers injected. Caller MUST consume task immediately.
    private func makeWebSocketRequest() throws -> URLRequest {
        // §A0.4: read Keychain → JSON-decode → stack-local creds → headers → release on return
        guard let credsData = try keychain.read(account: "volc-asr-credentials") else {
            throw BridgeError(code: "asr.credentials-missing",
                              message: "volc-asr-credentials not configured in Keychain")
        }
        let creds: VolcAsrCreds
        do {
            creds = try JSONDecoder().decode(VolcAsrCreds.self, from: credsData)
        } catch {
            throw BridgeError(code: "asr.credentials-malformed",
                              message: "volc-asr-credentials JSON decode failed")
        }
        guard !creds.appId.isEmpty, !creds.accessToken.isEmpty else {
            throw BridgeError(code: "asr.credentials-missing",
                              message: "appId or accessToken is empty")
        }

        let url = URL(string: Self.endpoint)!
        guard url.host?.lowercased() == Self.allowedHost else {
            throw BridgeError(code: "asr.host-not-allowed",
                              message: "host '\(url.host ?? "")' not in allow list")
        }

        let connectId = UUID().uuidString
        self.connectId = connectId

        var req = URLRequest(url: url)
        req.setValue(creds.appId,        forHTTPHeaderField: "X-Api-App-Key")
        req.setValue(creds.accessToken,  forHTTPHeaderField: "X-Api-Access-Key")
        req.setValue(Self.resourceId,    forHTTPHeaderField: "X-Api-Resource-Id")
        req.setValue(connectId,          forHTTPHeaderField: "X-Api-Connect-Id")
        // creds (and creds.accessToken) goes out of scope at function return → ARC release
        return req
    }
}
```

### 3.3 禁日志规则(具体 SOP + grep pattern)

**铁律**:任何 `os_log` / `print` / `NSLog` / `console.log` 涉及 ASR 通路的输出 **必须 redact** `appId` / `accessToken` / `Authorization` / `X-Api-Access-Key` 字符串本体。

**允许日志**(LLMGateway 同源):

- WS connect / disconnect 状态(state machine 转移)
- HTTP upgrade status code(101 / 401 / 403)
- 重连次数 / 退避 ms
- BridgeError code(纯机器读字符串,如 `asr.server-overload`)
- WS close code + close reason 字符串
- response 帧 message type(`0x9` server-full-response 等)
- `result.utterances` 数量(数字,不含原文)

**禁止日志**:

- `request.allHTTPHeaderFields`(整个字典含 `X-Api-Access-Key` 裸字符串)
- 任何 `creds.*` / `appId` / `accessToken` 变量字面量
- Bridge `asr-partial` / `asr-final` event 的 `text` 字段(可能含 PII;§A0.4 隐私分级)
- WS frame 二进制 raw bytes(可能含 PCM 即面试者声纹特征)
- PCM Data 的 base64 / hex dump

**Pre-commit grep SOP**(M2.8.dev.b 实施时**扩展** `scripts/check-no-key-leak.sh`,本 doc 锁规则):

## §4 Codable + 二进制帧打包 / 解包

### 4.1 双端模型对照表

| Swift Codable struct | JS Zod schema | 说明 |
|---|---|---|
| `VolcAsrCreds` | (Bridge 边界**不暴露**;§C3 锁) | `{appId: String, accessToken: String}`;Keychain JSON 解码;**不**进 nativeBridge.schemas.ts |
| `ASRAudioConfig` | `ASRAudioConfigSchema` | `{format: "pcm", rate: 16000, channels: 1, codec: "raw"}`(首帧 JSON `audio` 子结构) |
| `ASRRequestConfig` | `ASRRequestConfigSchema` | `{model_name: "bigmodel", enable_itn: bool, enable_punc: bool, enable_speaker_info: bool?}` |
| `ASRConfigPayload` | `ASRConfigPayloadSchema` | 首帧 full-client-request JSON:`{audio: ASRAudioConfig, request: ASRRequestConfig}` |
| `ASRUtterance` | `ASRUtteranceSchema` | response 单条 utterance:`{text: String, definite: Bool, start_time: Int?, end_time: Int?}` |
| `ASRResultPayload` | `ASRResultPayloadSchema` | response 帧 JSON 内层:`{result: {utterances: [ASRUtterance], text: String?}}` |
| `ASRStartParams` | `ASRStartParamsSchema` | Bridge `asr.start` params:`{streamId: String, enableITN: Bool?, enablePunc: Bool?}`(camelCase,Bridge 边界形态) |
| `ASRPartialPayload` | `ASRPartialPayloadSchema` | Event payload:`{text: String, definite: false}` |
| `ASRFinalPayload` | `ASRFinalPayloadSchema` | Event payload:`{text: String, definite: true, startTime: Int?, endTime: Int?}` |
| `ASREndPayload` | `ASREndPayloadSchema` | Event payload:`{reason: "stop" | "1011" | "1006" | "client-stop" | "eof"}` |
| `ASRErrorPayload` | `ASRErrorPayloadSchema` | Event payload(可选,见 §7.4):`{code: String, message: String}` |
| `ASRStatusResult` | `ASRStatusResultSchema` | `{connected: Bool, streamId: String?, retryCount: Int}` |

> **CodingKeys 注**:Swift 端首帧 JSON payload 用 snake_case(SAUC 协议要求 `model_name` / `enable_itn` 等,与 OpenAI compat 风格一致);Bridge 边界 `asr.*` method/event camelCase,与 LLMGateway §4 决策一致。

### 4.2 Swift Codable 关键签名(供 M2.8.dev.a 直接抄)

```swift
// apps/macos/Eatit/Bridge/Models/ASRMessages.swift (新建)

struct VolcAsrCreds: Codable {
    let appId: String
    let accessToken: String
}

struct ASRAudioConfig: Codable {
    let format: String     // "pcm"
    let rate: Int          // 16000
    let channels: Int      // 1
    let codec: String      // "raw"
}

struct ASRRequestConfig: Codable {
    let modelName: String          // "bigmodel"
    let enableITN: Bool             // 标点 normalization
    let enablePunc: Bool            // 标点
    let enableSpeakerInfo: Bool?    // optional;v3.4 默认 nil(不启用)
    enum CodingKeys: String, CodingKey {
        case modelName = "model_name"
        case enableITN = "enable_itn"
        case enablePunc = "enable_punc"
        case enableSpeakerInfo = "enable_speaker_info"
    }
}

struct ASRConfigPayload: Codable {
    let audio: ASRAudioConfig
    let request: ASRRequestConfig
}

struct ASRUtterance: Codable {
    let text: String
    let definite: Bool
    let startTime: Int?
    let endTime: Int?
    enum CodingKeys: String, CodingKey {
        case text, definite
        case startTime = "start_time"
        case endTime = "end_time"
    }
}

struct ASRResultInner: Codable {
    let utterances: [ASRUtterance]
    let text: String?      // 整段聚合文本(可选)
}

struct ASRResultPayload: Codable {
    let result: ASRResultInner
}

// Bridge 边界(camelCase)
struct ASRStartParams: Codable {
    let streamId: String
    let enableITN: Bool?
    let enablePunc: Bool?
}

struct ASRStatusResult: Codable {
    let connected: Bool
    let streamId: String?

```

### 4.3 二进制帧 4-byte custom header 设计

> **决策(标注:推断 — 待 M2.8.dev.a WebFetch 校验)**:
> 火山 SAUC bigmodel 的二进制帧采用一个紧贴 WebSocket Data frame payload 起始的 **4-byte custom header**,后面跟 JSON / PCM 二进制 payload。本 doc 按 SAUC 协议家族通行设计推断字节布局如下,**任何不一致**:M2.8.dev.a 第一个 step `WebFetch` 校验,architect 下个 loop 修订本 doc。

**4-byte custom header 字节定义**(big-endian / network byte order;每 byte 8 bits 高低位记法 [b7 b6 b5 b4 | b3 b2 b1 b0]):

| Byte | Bits | 含义 |
|---|---|---|
| `byte[0]` | b7..b4 | **Protocol version**(高 4 bit)— 锁 `0b0001` = `0x1` |
| `byte[0]` | b3..b0 | **Header size**(低 4 bit,以 4 字节为单位)— 锁 `0b0001` = `1`(本 header 共 4 字节) |
| `byte[1]` | b7..b4 | **Message type**(高 4 bit):`0x1` = full-client-request(首帧 config)/ `0x2` = client-audio-only-request(音频帧)/ `0x9` = server-full-response(server 推下行 partial+final)/ `0xB` = server-error-response |
| `byte[1]` | b3..b0 | **Message type specific flags**(低 4 bit):`0x0` = none / `0x1` = positive sequence / `0x2` = last-no-sequence(client 端结束信号)/ `0x3` = negative-with-sequence |
| `byte[2]` | b7..b4 | **Serialization method**(高 4 bit):`0x0` = no serialization(用于纯 PCM 帧)/ `0x1` = JSON / `0xF` = custom |
| `byte[2]` | b3..b0 | **Compression method**(低 4 bit):`0x0` = no compression / `0x1` = gzip(★ gzip flag bit 位置就在这★) |
| `byte[3]` | b7..b0 | **Reserved**:固定 `0x00` |

**典型帧字节实例**(供 M2.8.dev.a Hex 调试时对照):

| 帧类型 | 4-byte header(hex) | 解读 |
|---|---|---|
| 首帧 full-client-request(JSON,无压缩) | `0x11 0x10 0x11 0x00` | v=1, hdrSize=1, msgType=0x1, flags=0x0, ser=JSON, comp=none |
| 首帧 full-client-request(JSON + gzip) | `0x11 0x10 0x11 0x00`(若 b1.b3..b0 用 flags 表达 gzip 则改 byte[2]=`0x11`) | ser=JSON, comp=gzip → byte[2]=`0x11` |
| 音频帧 client-audio-only-request(无压缩 PCM) | `0x11 0x20 0x00 0x00` | msgType=0x2, ser=none, comp=none |
| 音频帧 + last 信号(client 主动收尾) | `0x11 0x22 0x00 0x00` | msgType=0x2, flags=0x2(last-no-sequence) |
| Server full-response(JSON 下行) | `0x11 0x90 0x11 0x00` | msgType=0x9, ser=JSON |
| Server error response | `0x11 0xB0 0x11 0x00` | msgType=0xB, ser=JSON |

> **spec 文本"[0x10, 0x10, 0x11, 0x00]" / "[0x11, 0x10, 0x11, 0x00]" 的复核**:
> spec line 1173 提到的具体字节 `[0x10, 0x10, 0x11, 0x00]` / `[0x11, 0x10, 0x11, 0x00]` 与本 §4.3 表中 "首帧 full-client-request(JSON, 无压缩)" 一栏的 `0x11 0x10 0x11 0x00` 在 **byte[0] 的高低位顺序**上推断一致(差异在 byte[0] 的版本/header-size 拼装方式),**M2.8.dev.a 必须 WebFetch 官方 doc 校验确切位序**。本 doc 把 spec 的字面字节作为"推断初值",但保留完整的字节-位含义表方便实施时按官方 doc 逐位校对。

### 4.4 Frame packing / unpacking 函数签名

```swift
// apps/macos/Eatit/Services/ASRGatewayFrame.swift (新建)
// 纯函数模块,M2.8.dev.a 优先实现 + 单测覆盖(零网络依赖)

enum ASRMessageType: UInt8 {
    case fullClientRequest = 0x1
    case clientAudioOnlyRequest = 0x2
    case serverFullResponse = 0x9
    case serverErrorResponse = 0xB
}

enum ASRSerialization: UInt8 {
    case none = 0x0
    case json = 0x1
}

enum ASRCompression: UInt8 {
    case none = 0x0
    case gzip = 0x1
}

struct ASRFrameHeader {
    let version: UInt8        // 4 bit;锁 0x1
    let headerSize: UInt8     // 4 bit;锁 0x1(=4 bytes)
    let messageType: ASRMessageType
    let flags: UInt8          // 4 bit
    let serialization: ASRSerialization
    let compression: ASRCompression
    // reserved byte[3] always 0x00
}

enum ASRFrameError: Error {
    case headerTooShort
    case unknownMessageType(UInt8)
    case unknownSerialization(UInt8)
    case unknownCompression(UInt8)
    case payloadDecodeFailed(String)
    case gzipFailed(String)
}

/// Pack first frame: full-client-request with JSON config payload.
/// gzip = true compresses payload (large config OR explicit policy);
/// v3.4 默认 false(payload < 200 bytes,gzip 反而更慢)。
func packFirstFrame(config: ASRConfigPayload, gzip: Bool = false) throws -> Data {
    var jsonData = try JSONEncoder().encode(config)
    var header = Data(count: 4)
    header[0] = (0x1 << 4) | 0x1                    // ver=1, hdrSize=1
    header[1] = (ASRMessageType.fullClientRequest.rawValue << 4) | 0x0   // msgType=0x1, flags=0
    header[2] = (ASRSerialization.json.rawValue << 4) | (gzip ? ASRCompression.gzip.rawValue : 0)
    header[3] = 0x00
    if gzip {
        jsonData = try gzipCompress(jsonData)        // implementation in §4.5
    }
    return header + jsonData
}

/// Pack audio frame: 6400 bytes PCM payload + 4-byte header (no serialization, no compression).
/// last=true sets flags bit to 0x2 (signal client-side stream end).
func packAudioFrame(pcmChunk: Data, last: Bool = false) -> Data {
    precondition(pcmChunk.count == 6400 || last,
                 "expect 6400-byte PCM chunk (M2.6 lock); only last frame may differ")
    var header = Data(count: 4)
    header[0] = (0x1 << 4) | 0x1
    header[1] = (ASRMessageType.clientAudioOnlyRequest.rawValue << 4) | (last ? 0x2 : 0x0)
    header[2] = (ASRSerialization.none.rawValue << 4) | 0x0     // raw PCM, no compression
    header[3] = 0x00
    return header + pcmChunk
}

/// Unpack server response frame: header + JSON ASRResultPayload (or error envelope).
func unpackResponseFrame(data: Data) throws -> ASRResponse {
    guard data.count >= 4 else { throw ASRFrameError.headerTooShort }
    let h0 = data[0], h1 = data[1], h2 = data[2]
    let msgTypeRaw = (h1 >> 4) & 0x0F
    guard let msgType = ASRMessageType(rawValue: msgTypeRaw) else {
        throw ASRFrameError.unknownMessageType(msgTypeRaw)
    }
    let serRaw = (h2 >> 4) & 0x0F
    let compRaw = h2 & 0x0F
    var payload = data.subdata(in: 4..<data.count)
    if compRaw == ASRCompression.gzip.rawValue {
        payload = try gzipDecompress(payload)
    }
    switch msgType {
    case .serverFullResponse:
        let result = try JSONDecoder().decode(ASRResultPayload.self, from: payload)
        return .result(result)
    case .serverErrorResponse:
        let env = try JSONDecoder().decode(ASRServerErrorEnvelope.self, from: payload)
        return .serverError(env)
    default:
        throw ASRFrameError.unknownMessageType(msgTypeRaw)
    }
    _ = (h0, serRaw)  // version & ser already implicitly checked
}

enum ASRResponse {
    case result(ASRResultPayload)
    case serverError(ASRServerErrorEnvelope)
}
```

### 4.5 gzip 压缩 / 解压(payload 较大时)

v3.4 **首帧默认不开 gzip**(payload ~150 bytes,压缩成本 > 收益)。但 receive 路径必须支持 server 端 gzip 下行(server 可能压缩长文本结果)。

```swift
import Compression

private func gzipCompress(_ data: Data) throws -> Data {
    // Foundation NSData(data:).compressed(using: .zlib) 或 Compression.framework
    // M2.8.dev.a 实施时选成熟封装(如 SwiftCompression 库 OR 直接 NSData.compressed),
    // **不**新增第三方 SPM 依赖;Foundation Compression 已在 macOS 11+
    return try (data as NSData).compressed(using: .zlib) as Data
}

private func gzipDecompress(_ data: Data) throws -> Data {
    return try (data as NSData).decompressed(using: .zlib) as Data
}
```

> **决策**:用 Foundation `NSData.compressed(using: .zlib)`,**不**引入第三方 gzip SPM 包。理由:macOS 11+ 自带,零依赖,审核风险低。

## §5 WebSocket 连接 + 首帧 full-client-request

### 5.1 connect() 完整流程

```swift
extension ASRGateway {
    /// Connect WS, send first frame, await server ack. Throws on failure.
    func connect(streamId: String, params: ASRStartParams) async throws {
        guard task == nil else {
            throw BridgeError(code: "asr.already-connected",
                              message: "another stream is active: \(self.streamId ?? "?")")
        }
        let req = try makeWebSocketRequest()        // §3.2
        let session = URLSession(configuration: .default)
        let task = session.webSocketTask(with: req)
        task.resume()
        self.task = task
        self.streamId = streamId

        // Send first frame (full-client-request)
        let config = ASRConfigPayload(
            audio: ASRAudioConfig(format: "pcm", rate: 16000, channels: 1, codec: "raw"),
            request: ASRRequestConfig(
                modelName: "bigmodel",
                enableITN: params.enableITN ?? true,
                enablePunc: params.enablePunc ?? true,
                enableSpeakerInfo: nil
            )
        )
        let firstFrame: Data
        do {
            firstFrame = try packFirstFrame(config: config, gzip: false)
        } catch {
            throw BridgeError(code: "asr.frame-pack-failed",
                              message: "first frame pack: \(error)")
        }
        do {
            try await task.send(.data(firstFrame))
        } catch {
            self.task = nil
            self.streamId = nil
            throw BridgeError(code: "asr.ws-handshake-failed",
                              message: "first frame send failed: \(error)")
        }

        // Spawn receive loop (detached Task; events go via BridgeRouter.dispatchEvent)
        Task { [weak self] in
            await self?.receiveLoop()
        }
    }
}
```

### 5.2 ASRConfigPayload 完整字段(供 M2.8.dev.a JSON encode 单测对照)

```json
{
  "audio": {
    "format":   "pcm",
    "rate":     16000,
    "channels": 1,
    "codec":    "raw"
  },
  "request": {
    "model_name":  "bigmodel",
    "enable_itn":  true,
    "enable_punc": true
  }
}
```

> **字段值锁定**:
> - `audio.format = "pcm"`(raw 16-bit signed little-endian PCM,M2.6 AudioCaptureService 已锁)
> - `audio.rate = 16000`(M2.6 AudioCaptureService.targetSampleRate 已锁)
> - `audio.channels = 1`(M2.6 mono)
> - `audio.codec = "raw"`(无 wav 头,纯 PCM bytes)
> - `request.model_name = "bigmodel"`(SAUC bigmodel 标识符,推断 — M2.8.dev.a WebFetch 校验)
> - `request.enable_itn` / `request.enable_punc`:从 `ASRStartParams` 透传,默认 true

### 5.3 等待 server ack 策略 — **不阻塞 connect()**

> **决策**:`connect()` 发送首帧后 **立刻返回 success**,**不**阻塞等待 server 第一个 response 帧。理由:
> 1. SAUC 协议在收到首帧 + 任何音频帧之前不会主动下发 ack(server 是被动等待 PCM 才开始 push utterance)
> 2. 阻塞等待 ack 反而会让 audio.start → asr.start 时序卡住,UI 体验差
> 3. 若 server 实际拒绝(如 401)会在很短时间内 close WS 并附带 close code,receive loop 会立即捕获并 emit `asr-error`
> 4. 真调失败的快速反馈(< 200ms)足够;不需要 connect-time ack 同步等待

**反例(本设计拒绝)**:`await waitForFirstFrame()` 在 connect() 内同步等服务器响应 — 协议无 ack 概念,实际是死等。

### 5.4 connect() 失败回收

任何 connect() 内部 throw 都必须保证:
- `self.task` 重置为 nil
- `self.streamId` 重置为 nil
- 尚未 resume 的 task **必须** `cancel()`(防止 URLSessionWebSocketTask 泄漏)
- AudioCaptureService 的 PCM callback **不**被注册(`audio.start` 还未链上 `asr.start`,见 §6)

### 6.2 handlePCMChunk 实现

```swift
extension ASRGateway {
    /// Called by AudioCaptureService on background audio thread,
    /// per 6400-byte (200ms) chunk. §C3: in-process Swift; PCM never crosses Bridge.
    func handlePCMChunk(_ pcmChunk: Data) {
        guard let task = self.task, task.state == .running else {
            // Silent drop: WS not connected; AudioCaptureService is over-eager.
            // Don't error-log here (would spam at 5 Hz);
            // §10 testStreamContinuesIfWSDrops 覆盖该路径行为.
            return
        }
        let frame = packAudioFrame(pcmChunk: pcmChunk, last: false)
        Task { [weak self] in
            do {
                try await task.send(.data(frame))
            } catch {
                self?.dispatchError(code: "asr.frame-send-failed",
                                    message: "audio frame send: \(error)")
                await self?.attemptReconnect()
            }
        }
    }
}
```

### 6.3 推流速率 + buffer 策略

- AudioCaptureService 已锁 6400 bytes / 200ms,即 **5 帧/秒** 上行;火山协议默认接受 100-200ms / 帧(SAUC 限速友好)
- **不**做 client-side buffering / batching:每 6400-byte chunk 就 send 一次;low-latency
- 如果 WS send 比 PCM 产出慢(网络拥塞):`task.send` 是 async,排队;**不**主动丢帧;若排队超过 10 帧(2s)→ emit `asr-network-slow` warning event(可选,M2.8.dev.c 视情况实现;v3.4 acceptance 不强求)

### 6.4 关闭时的 last 帧

`asr.stop` 收到时,先发送 **flags = 0x2 last-no-sequence** 的 0-byte audio 帧通知 server "client side stream ended",然后等待 1s 内的 server final response,再 close WS 1000。

```swift
extension ASRGateway {
    func disconnect(graceful: Bool = true) async {
        guard let task = self.task else { return }
        if graceful {
            // Send last flag (zero-byte PCM with last bit set)
            let lastFrame = packAudioFrame(pcmChunk: Data(), last: true)
            try? await task.send(.data(lastFrame))
            // Give server ~1s to flush final results
            try? await Task.sleep(nanoseconds: 1_000_000_000)
        }
        task.cancel(with: .normalClosure, reason: nil)
        self.task = nil
        self.streamId = nil
        dispatchEvent(type: "asr-end", payload: ["reason": graceful ? "client-stop" : "abrupt"])
    }
}
```

## §7 Receive loop + partial / final 解析 + Bridge events

### 7.1 receive loop 主循环

```swift
extension ASRGateway {
    /// Loop receiving WS frames; dispatch BridgeEvent on each utterance.
    /// Runs on a detached Task; exits on WS close or fatal decode error.
    private func receiveLoop() async {
        guard let task = self.task else { return }
        while task.state == .running {
            let msg: URLSessionWebSocketTask.Message
            do {
                msg = try await task.receive()
            } catch {
                await handleReceiveError(error)
                return
            }
            switch msg {
            case .data(let frameData):
                handleFrame(frameData)
            case .string:
                // SAUC 不发 text frames; ignore defensively
                continue
            @unknown default:
                continue
            }
        }
    }

    private func handleFrame(_ data: Data) {
        let resp: ASRResponse
        do {
            resp = try unpackResponseFrame(data: data)
        } catch ASRFrameError.payloadDecodeFailed(let why) {
            dispatchError(code: "asr.frame-unpack-failed", message: why)
            return
        } catch {
            dispatchError(code: "asr.frame-unpack-failed", message: "\(error)")
            return
        }
        switch resp {
        case .result(let r):
            dispatchUtterances(r.result.utterances)
        case .serverError(let env):
            dispatchError(code: "asr.server-error",
                          message: "[\(env.error.code)] \(env.error.message)")
        }
    }

    private func dispatchUtterances(_ utterances: [ASRUtterance]) {
        for u in utterances {
            let payload: [String: Any] = u.definite
                ? ["text": u.text, "definite": true,
                   "startTime": u.startTime as Any, "endTime": u.endTime as Any]
                : ["text": u.text, "definite": false]
            let type = u.definite ? "asr-final" : "asr-partial"
            router?.dispatchEvent(type: type, streamId: self.streamId ?? "", payload: payload)
        }
    }
}
```

### 7.2 partial vs final 决策点

**唯一判定**:`utterance.definite` boolean:

| `definite` | event type | UI 行为(给 M3.4 提示) |
|---|---|---|
| `false` | `asr-partial` | 实时滚动显示,后续 partial 覆盖前一个 partial 的同一行 |
| `true` | `asr-final` | 锁定一段(commit),不再被后续 partial 覆盖,准备下一段 |

**单帧多 utterance 处理**:server 可能在一帧 response 里返回多条 utterance(混合 partial + final);receive loop 按数组顺序逐条 dispatch,**保持顺序**。

### 7.3 BridgeEvent payload 形态

| event type | payload (JSON, camelCase) |
|---|---|
| `asr-partial` | `{ text: string, definite: false }` |
| `asr-final` | `{ text: string, definite: true, startTime?: int, endTime?: int }` |
| `asr-end` | `{ reason: "stop" \| "1011" \| "1006" \| "client-stop" \| "eof" }` |
| `asr-error`(可选,见 §7.4) | `{ code: string, message: string }` |

### 7.4 决策:asr-error 的承载

> **决策**:**不新增** `asr-error` BridgeEvent enum case(避免改 BridgeEventSchema)。错误统一通过 `asr-end` 的 `reason` 字段表达 + Bridge method 层 throw BridgeError(`asr.start` / `asr.stop` 调用如果失败直接 throw)。
>
> 理由:
> 1. BridgeEventSchema 已稳定 7 个 case(M2.7.dev.c 定型),避免再改
> 2. `asr-end` 自带 reason 已能区分 normal / 1011 / 1006 / eof / client-stop
> 3. 真正致命错误(connect 失败 / 401)发生在 `asr.start` Bridge method 同步阶段,由 method 直接 throw BridgeError;不需要 event 通道
> 4. **唯一例外**:receive loop 里的 frame-decode-failed 等"流中错误"采用 `asr-end` reason="error" + `errorCode` extra field(下表)
>
> **替代方案(若 M3.4 实施时发现 reason 字符串不够区分)**:架构允许下个 loop 在 `asr-end` payload 加可选 `errorCode: string` 字段(追加,不破坏 backward compat)
>
> **本 doc 采纳的最终 payload schema**:`asr-end.payload = { reason, errorCode?, errorMessage? }`(reason="error" 时强制带后两者)

```ts
export const ASREndPayloadSchema = z.object({
  reason: z.enum(["stop", "client-stop", "eof", "1011", "1006", "error"]),
  errorCode: z.string().optional(),
  errorMessage: z.string().optional(),
});
```

### 7.5 receive loop 对 URLError / 取消的鲁棒性

`task.receive()` 在以下情况抛出:
- WS server 关闭(close code 已通过 task.closeCode 暴露,但 receive() 直接抛 cancel-like Error)
- 网络中断(`URLError(.networkConnectionLost)` 等)
- 本地主动 cancel(`task.cancel(with:reason:)`)→ receive() 抛 CancellationError-like

`handleReceiveError(_:)` 统一分类(见 §8)。

## §8 错误处理 + 重连策略

### 8.1 close code → 行为表

| close code | 含义 | 行为 |
|---|---|---|
| `1000` Normal Closure | server / client 主动关 | emit `asr-end` reason="stop";**不**重连 |
| `1011` Internal Error / Server Overload | 火山限流 / 服务过载 | 退避重连 ×3(0.5s, 1.0s, 2.0s);失败则 emit `asr-end` reason="1011" + errorCode="asr.server-overload" |
| `1006` Abnormal Closure(无 close frame) | 网络底层断 | 退避重连 ×3;失败则 emit `asr-end` reason="1006" + errorCode="asr.network-drop" |
| `1002` Protocol Error | 我方帧打错 | **不**重连(retry 也是同样的 bug);emit `asr-end` reason="error" + errorCode="asr.frame-pack-failed" |
| `1008` Policy Violation | 鉴权失败 / appId 错 / 配额超 | **不**重连(重试也无效);emit `asr-end` reason="error" + errorCode="asr.api-key-invalid" |
| 其它 1xxx / 4xxx | 未分类 | 重连 1 次后放弃;emit `asr-end` reason="error" + errorCode="asr.ws-close-unknown" |
| `URLError(.networkConnectionLost)` | 受 OS 网络断检测 | 同 1006 |
| `URLError(.notConnectedToInternet)` | 无网 | **不**重连(用户没网,重试无意义);emit `asr-end` reason="error" + errorCode="asr.no-network" |

### 8.2 退避重连实现

```swift
private var retryCount: Int = 0
private static let backoffMs: [UInt64] = [500, 1000, 2000]

private func attemptReconnect() async {
    guard retryCount < Self.backoffMs.count else {
        dispatchEvent(type: "asr-end", payload: [
            "reason": "1011",
            "errorCode": "asr.server-overload",
            "errorMessage": "retry exhausted after \(retryCount) attempts"
        ])
        self.task = nil
        self.streamId = nil
        return
    }
    let delay = Self.backoffMs[retryCount]
    retryCount += 1
    try? await Task.sleep(nanoseconds: delay * 1_000_000)
    do {
        try await reconnectSilent()  // 同 connect 流程,但保留 streamId,不发 asr-start event
    } catch {
        await attemptReconnect()       // recurse;exit on retryCount cap
    }
}
```

**重要不变量**:重连过程中 **AudioCaptureService 不停**(M2.6 PCM 流持续);重连成功后 `handlePCMChunk` 自然恢复;重连期间 PCM 帧静默丢弃(§6.2 已实现 `task.state != .running` 时 silent drop)。这与 LLM SSE 不同(LLM 没有"持续输入流",ASR 有),设计上明确区分。

### 8.3 鉴权失败(401 / WS Upgrade 失败)

URLSessionWebSocketTask 对 HTTP 401 的暴露形态比 dataTask 弱(WS Upgrade 阶段失败会让后续 `task.send` / `task.receive` 直接抛 URLError)。M2.8.dev.b 单测覆盖:

```swift
// XCTest mock URLProtocol returning 401 to upgrade
let task = URLSession.shared.webSocketTask(with: req)
task.resume()
do {
    try await task.send(.data(firstFrame))
    XCTFail("should throw")
} catch {
    // 鉴权失败的标志是 task.closeCode == .policyViolation OR HTTP 401
    XCTAssertEqual(task.closeCode, .policyViolation)
}
```

**分类规则**:
- `task.closeCode == .policyViolation` (1008) → `asr.api-key-invalid`
- `task.closeCode == .normalClosure` (1000) 但发生在 send 第一帧前 → `asr.ws-handshake-failed`
- 其它 → `asr.ws-connect-failed`

## §11 反模式拒绝清单(显式回引 §K + 永久排除)

本设计 **明确拒绝** 以下做法。M2.8.dev 实施过程中如有 subagent / contributor 提议任一条,**当场拒绝并报告**。

### ❌ 反模式 1: 先用 Python sidecar 跑 faster-whisper 作为本地 ASR 兜底(§K #2 直击)

> 提议:"火山协议太复杂,先 spawn 一个 Python sidecar 跑 faster-whisper,让 v3.4 demo 能跑通,后面再补 SAUC。"

**拒绝**:
1. §A0 总纲 + 永久排除清单明确禁止 Python sidecar / faster-whisper
2. Mac App Store 不允许打包 Python 解释器(library validation)
3. faster-whisper 模型 ~150MB-3GB 增加 app bundle 体积,过审风险
4. 一旦 PR 进了主线,后面"补 SAUC"动力消失 → 永久 sidecar 化
5. ASR 通路必须 100% 火山 SAUC,无 fallback。如果 SAUC 不可达,UI 应该显式告知"网络异常",不应该静默切到本地 ASR 制造一种"工作中"的假象

### ❌ 反模式 2: 在 WKWebView 内用 Web Worker 跑 WebSocket 调试 ASR(§K #4 直击)

> 提议:"为了让前端工程师能独立调试 ASR,在 React 侧用浏览器原生 WebSocket 直连火山,Swift 只负责 PCM 推过去。"

**拒绝**:
1. WKWebView 内 fetch/WS 不走 sandbox 友好路径(部分 origin policy 不可控)
2. **§C3 PCM 字节绝对不能出 Swift 边界**;让 JS 拿到 PCM = 推翻整个总纲
3. accessToken 进 JS = §K #6 反模式直击
4. 双端两个 WS 实现 = 维护两份解析逻辑
5. 调试方便不是放弃总纲的理由;mock URLProtocol + 本机 ws://localhost:port testHelper 已经能覆盖 95% 调试场景

### ❌ 反模式 3: 把 accessToken 通过 messageHandler 传给 JS 临时存内存(§K #6 直击)

> 提议:"JS 启动时 `bridge.call('keychain.read', {account:'volc-asr-credentials'})` 拉一次,JS 端做 WS 握手时拼 X-Api-Access-Key header。"

**拒绝**:
1. JS 内存对 sandbox 外的 attacker 视作可读(WebKit JIT、devtools、远程 XSS via 第三方依赖供应链)
2. `keychain.read` Bridge method **从未注册**(M2.2 故意只暴露 save/exists/delete)
3. Keychain `kSecAttrAccessibleAfterFirstUnlock` 提供的 OS 级保护一旦"过桥"立即失效
4. App Store review 历史记录:任何把 API key 持久化到 WebView storage / `localStorage` / IndexedDB 的设计有被拒先例(Guideline 5.1.1 / 5.1.2)
5. 与 LLMGateway §3 决策同源

### ❌ 反模式 4: 为 ASR 调试方便加 disable-library-validation(§K #7 直击)

> 提议:"调试 SAUC 二进制帧时,临时加 `com.apple.security.cs.disable-library-validation` 让某第三方 gzip 库 dlopen 通过。"

**拒绝**:
1. §A0.2 entitlement 黑名单铁律,disable-library-validation 永久禁
2. 第三方 gzip 库不必要:Foundation `NSData.compressed(using: .zlib)` 自带,§4.5 已锁
3. 一旦 entitlements.plist 加进 git,review 期被发现 = App Store 拒
4. 真正需要 dynamic loading 的场景在 Mac App Store 是几乎不存在的;沿用 system framework

### ❌ 反模式 5: 为让 Swift 端 spawn 调试工具,加 network.server entitlement(§K #8 直击)

> 提议:"为了让 XCTest 能起本地 ws://localhost:8080 mock SAUC server,加 `com.apple.security.network.server` entitlement。"

**拒绝**:
1. **运行时 app**(发布版)绝对不需要 server,只需 client(URLSessionWebSocketTask 是 client)
2. **测试** target 与 app target entitlement 解耦:XCTest 是单独 target,有自己的 testHostBundleIdentifier;XCTest target 可以不加 sandbox(macOS XCTest 默认 sandbox-free),Test helper 起本机 NWConnection 自由

4. §A0.2 entitlement 黑名单针对的是 production app,本节点不变

### 13.3 字段不一致时的处理路径

**developer 收到 WebFetch 结果后**:

1. 把官方 spec 与本 doc §4.3 / §5.2 / §2.1 表逐项对照,生成一份 diff
2. **任何**字节布局 / 字段名 / 字段值不一致 → 立即停下,**不**自行硬编码
3. 在 fix_plan.md 暗示路径(让 Ralph 主进程感知,**developer 不直接改 fix_plan**):commit message body 写一段 "M2.8.dev.a halted: SAUC protocol mismatch (本 doc §4.3 byte[1] high-nibble 0x1 vs official: 0xN). Architect re-loop required."
4. Ralph 主进程下个 loop 重派 architect 修订本 doc,M2.8.dev.a 重启

**反模式(本 doc 拒绝)**:

> "WebFetch 拿到的官方 doc 与 design 略有差异,我直接按 doc 改代码,don't bother architect。"

→ 拒绝。本 design doc 是单一事实源,**任何**字段微调必须 architect re-loop。Developer 的职责是按 doc 实施 + 反馈差异,**不**是改 doc 也不是按 doc 之外的"发现"硬编码。

### 13.4 真调失败的回退路径

若 M2.8.dev.e 真调 SAUC 失败(connect 401 / 二进制帧 server reject):

1. 优先怀疑 §13.1 表中的字段值(资源 ID 字符串 / model_name 字符串)
2. 其次怀疑 §4.3 字节布局位序
3. 检查 Keychain `volc-asr-credentials` JSON 格式(用户可能写错)
4. 网络层用 `nscurl --ats-diagnostics` 验证 ATS 配置
5. **不**为调试加 entitlement / 关 ATS / 把 key 露给 JS
