## 1. 目标与范围

本设计是 **M3.4.1.dev** 落地"按住空格 → 实时字幕 → 松手提交 turn"流程的唯一依据,并为 **M3.4.X tester re-audit**(首字 < 800ms、松手 < 1.5s)给出延迟预算。

**包含**:`volcStreamAsr.ts` 高层协调器 API、状态机、对 `useASRStream` 的封装策略;`LiveCaption.tsx` 纯展示组件 props 与渲染规则;InterviewPage 从 v3.3 后端 WebSocket 到 v3.4 Bridge 流式 ASR 的迁移路径;延迟预算分层。

**不包含**:Swift `ASRGateway` 内部实现(M2.8 已封板)、Volc SAUC 协议细节(M2.8 design doc §3 / §4)、turn_graph 节点函数(M3.3.1)、按住空格的全局快捷键监听(M5 集中处理)。

**v3.3 legacy WebSocket 必须删除**。InterviewPage 当前(line 291–340)走 `ws://${API_BASE_URL}/ws/sessions/{sid}?token=mock`,服务端 mock Azure ASR 推 `server.transcript.partial / final`。该路径在 macOS App Store 上不可生:Tauri / Python sidecar / `network.server` entitlement 永久排除(L0 §K + 反模式 #4)。v3.4 唯一合法链路是 **Bridge → Swift ASRGateway → Volc SAUC**,JS 一侧只能消费已转写的文本事件。

## 2. L0 红线

- **§K #4 PCM 不过 Bridge**(L0):JS 一侧 NEVER 见到 raw audio bytes。`volcStreamAsr` 包装的 `useASRStream` 只 yield `{type:"partial"|"final", text}` — 文本事件。任何"为了调试方便把 PCM 透传到 JS"的提议本 doc **明确拒绝**(§K #6 反模式)。
- **§C3 secret 不过 Bridge**(L0):JS 永远看不到 `ARK_API_KEY` / `volc-asr-credentials` / `X-Api-Access-Key`。`asrStart(params)` 只透传 `streamId / enableITN / enablePunc`;Swift `ASRGateway` 内部读 Keychain 注入 4 个鉴权 header。`createVolcStreamAsr(options)` 的 `options` 字段 **禁止**包含任何形如 `apiKey / accessToken / appId` 的字段;Zod 已在 `ASRStartParamsSchema` 锁死。
- **反模式 #4 拒绝**:不得引入 browser `MediaRecorder` 推流到 Volc;不得在 JS 直接 `new WebSocket("wss://openspeech.bytedance.com/...")`。Bridge → Swift WS 是唯一合法链路。InterviewPage 现存 `createAudioRecorder + socket.send(buffer)` 块(line 473–491)整体删除,**不保留**任何 fallback。
- **BridgeEvent enum 已封板**:`asr-partial / asr-final / asr-end` 三事件覆盖所有需要;**本节点不新增** event type。`asr-error` 不存在 — 错误以 `asr-end` 携带 `reason:"error"` 上抛(M2.8 design §7.4)。
- **§A11 PII**:`partial.text / final.text` 是用户原话,属 PII。`volcStreamAsr` 内部禁止 `console.log(text)` / 上报 telemetry 时禁止带文本本体;只允许记录 `text.length / chunk.type / state transition`。
- **性能门禁**(M3.4.X 验收):首字 < 800ms(空格按下到第一个 partial 渲染上屏)、松手 < 1.5s(空格抬起到 final 落 turn_graph)。§7 给出分层预算。

## 4. `volcStreamAsr.ts` API 与状态机

### 4.1 公共类型与控制器

```ts
// apps/desktop/src/core/asr/volcStreamAsr.ts

export interface CaptureResult {
  finalText: string;
  startTime?: number;   // ms, from Volc final payload (optional)
  endTime?: number;
}

export interface VolcStreamAsrCallbacks {
  onPartial(text: string): void;     // each partial REPLACES previous text (Volc 是可修订的 interim)
  onError?(err: Error): void;        // bubble Bridge / Swift errors;UI 展示 + 自动 abort
}

export type VolcStreamAsrState =
  | "idle" | "capturing" | "draining" | "done" | "errored";

export interface VolcStreamAsrController {
  beginCapture(callbacks: VolcStreamAsrCallbacks): void;
  endCapture(): Promise<CaptureResult>;
  abort(): void;
  readonly state: VolcStreamAsrState;     // 只读,debug / 测试断言用
}

export function createVolcStreamAsr(
  options?: { enableITN?: boolean; enablePunc?: boolean }
): VolcStreamAsrController;
```

### 4.2 状态机(单实例 lifecycle)

```
idle ──beginCapture──► capturing ──endCapture──► draining ──final received──► done
  ▲                       │                          │
  │                       └─ abort / onError ────────┴──► errored ──reset?──► idle
  └─ createVolcStreamAsr()
```

- **idle**:初始状态;`endCapture()` 此时 reject `"asr.not_capturing"`。
- **capturing**:已 `await asrStart` + `audio.start`,`for await (chunk of useASRStream())` 循环跑;每个 partial chunk 走 `onPartial(text)`。
- **draining**:`endCapture` 已调用,iterator.return() 已触发,`useASRStream` finally 已开始(audio.stop → asrStop)。等待最后一个 `asr-final` 事件。**最长等待 1.5s**(与 Swift drain 1s 同量级,留 500ms buffer);超时则 reject `"asr.no-final-received"`(§7 风险点)。
- **done**:已 resolve `Promise<CaptureResult>`;再次 `endCapture` reject `"asr.not_capturing"`。
- **errored**:`onError(err)` 已派发,内部已 abort + 清理;`endCapture` reject 同一 error;`beginCapture` 可重新进入 capturing(controller 可复用)。

### 4.3 实现策略(developer 翻译指引)

- 内部持 `iter: AsyncGenerator<ASRStreamChunk> | null` 与 `pendingFinal: { resolve, reject } | null`。
- `beginCapture(cb)` 同步:置 `state = "capturing"`,`iter = useASRStream(options)`,启动 `void runLoop()` 后台任务。**不 await**;若 `asrStart` 失败,错误从 generator 的第一次 `next()` 抛出,`runLoop` 内部 catch → `state = "errored"` + `cb.onError(err)`。
- `runLoop`:`for await (const chunk of iter)`;`partial` → `cb.onPartial(chunk.text)`(注意 partial 是 **替换**,不是 append — Volc SAUC 中间结果可被修订;`onPartial` 调用方持有"当前最新整句")。`final` → 缓存 `lastFinal = { text, startTime, endTime }`;若 `pendingFinal` 已存在,立即 resolve 并 return。
- `endCapture()`:若 `state !== "capturing"` reject `"asr.not_capturing"`。否则 `state = "draining"`,返回 `new Promise<CaptureResult>((resolve, reject) => { pendingFinal = {resolve, reject}; setTimeout(() => reject("asr.no-final-received"), 1500); iter.return(); })`。`iter.return()` 触发 `useASRStream` 的 finally(audio.stop → asrStop);Swift 收到 stop → 发 last-flag → 等 Volc 回 final → emit `asr-final` + `asr-end`。`runLoop` 在 finally 跑完前还会消费到 final chunk(取决于事件竞速),所以两条路径都有可能 resolve:**先到先得**。
- `abort()`:`state = "errored"`(若不在 done);`iter?.return()`;`pendingFinal?.reject("asr.aborted")`。
- `onError` 来源:`runLoop` 的 try/catch(`useASRStream` 内 throw — 例如 `asr-end reason="error"` 时抛出 `[errorCode] errorMessage`)。

### 4.4 为什么不直接把 `useASRStream` 暴露给 InterviewPage

- **React 状态与 AsyncIterator 不组合**:`for await` 只能在 effect 内挂载;按住空格的 imperative `start/stop` 语义和 iterator pull 模型互斥;状态需要逐 partial 走 `setState` + 可能 `flushSync`,iterator 嵌套 setState 会引入 useState batching 死区。
- **press-and-hold UI 想要 `beginCapture()` / `endCapture()` 这种命令式 API**,而不是把迭代器对象传进 ref。
- **partial 聚合策略集中在 controller**(每个 partial 替换上一份),InterviewPage 只关心 `onPartial(text)` callback,UI 与流水线解耦。
- **错误分流**:`asr-end reason="error"` 在 controller 内部转 `onError`,InterviewPage 不需要识别"end-without-final"这种状态机问题。

## 6. `LiveCaption.tsx` 组件规约

### 6.1 Props 与接口

```tsx
// apps/desktop/src/pages/interview/LiveCaption.tsx
export interface LiveCaptionProps {
  partialText: string;     // 来自 onPartial,空串=未出字
  finalText: string;       // turn_graph 提交前的最终文本;空串=尚未 final
  isCapturing: boolean;    // state.context.isRecording 的镜像
}
export const LiveCaption: React.FC<LiveCaptionProps>;     // React.memo 包裹
```

### 6.2 渲染规则(状态决定 UI)

| isCapturing | partialText | finalText | UI |
|---|---|---|---|
| true | "" | (任意) | "正在聆听..." 占位文案 + 脉冲点 |
| true | non-empty | (任意) | 渲染 `partialText`,斜体 / 浅灰(pre-final 视觉) + 脉冲点 |
| false | (任意) | non-empty | 渲染 `finalText`,常态字重 / 主色 |
| false | (任意) | "" | 不渲染(返回 `null`) |

### 6.3 性能与 a11y

- `React.memo(LiveCaption, (prev, next) => prev.partialText === next.partialText && prev.finalText === next.finalText && prev.isCapturing === next.isCapturing)` — 父组件 100ms 内可能多次 re-render,memo 是必须。
- partial 区用 `aria-live="polite"`(屏幕阅读器节流播报中间结果);final 区用独立 `<p>`,不带 `aria-live`(避免与 polite 区域内容竞争)。
- 不使用 `dangerouslySetInnerHTML`;text 是普通字符串,React 自动转义。
- 视觉 token 沿用现有设计系统(色板 / spacing);若缺,占位 hardcode + 在 §11 列为 M5 待办。

## 7. 延迟预算(M3.4.X 性能门禁)

### 7.1 首字延迟(target < 800ms)

| 阶段 | 预算 | 备注 |
|---|---|---|
| 空格 keydown → React onMouseDown / 全局快捷键监听器触发 | < 5ms | M5 全局快捷键 + React event |
| `handleVoiceStart` → `controllerRef.current.beginCapture()` 同步 ref 调用 | < 5ms | |
| `useASRStream` first `next()` → `asrStart` Bridge 调用 | < 50ms | Bridge IPC roundtrip |
| `asrStart` → Volc WS 握手 + 第一帧 | < 400ms | 网络 RTT + WSS 握手(冷启动);好网络通常 < 200ms |
| `audio.start` → AVAudioEngine 第一个 PCM buffer | < 50ms | AudioUnit 冷启 |
| 第一份 PCM → Volc 回 partial | < 200ms | Volc SAUC interim 典型延迟 |
| `bridge emit asr-partial` → `useASRStream` yield → `onPartial` → `setState` → React paint | < 50ms | bridge.on dispatch + commit phase |
| **合计** | **≈ 760ms(margin 40ms)** | 紧张 |

**风险**:Volc WS 冷启动握手在弱网下 > 400ms 概率不小。M3.4.X 在好网/弱网各测一组;若弱网下首字 800ms 不可达,M3.5 考虑 **预热**(InterviewPage 进入"对话准备"状态时先 `asr.warmup` 打握手,空格按下时复用已建连)— 本节点不实施,但 controller API 不阻塞这条优化路径。

### 7.2 松手到 final(target < 1500ms)

| 阶段 | 预算 |
|---|---|
| 空格 keyup → `handleVoiceStop` → `endCapture()` | < 10ms |
| iterator.return() → `useASRStream` finally → `audio.stop()` Bridge | < 30ms |
| Swift 发 last-flag 帧 → Volc 回 final → `asr-final` event | < 1000ms(Swift drain 1s 上限) |
| `asr-final` → `useASRStream` yield → controller resolve `Promise` | < 30ms |
| `endCapture()` resolve → `send({TRANSCRIPT_FINAL})` → turn_graph.invoke 起点 | < 50ms |
| **合计** | **≈ 1120ms(margin 380ms)** |

`volcStreamAsr` 内部 1500ms 超时(§4.3)= 业务上限;超时则 reject `"asr.no-final-received"`,UI 应展示"识别超时,请重试"并允许 fallback 到文本输入。

## 9. 可观察性(无 PII)

`volcStreamAsr` 内部(若开 debug build)**只**允许结构化日志:
```
{ kind:"asr.state", from:"capturing", to:"draining", ts: Date.now() }
{ kind:"asr.partial.recv", textLen: 12, ts:... }      // 不带 text 本体
{ kind:"asr.final.recv", textLen: 28, startTime:..., endTime:... }
{ kind:"asr.error", code:"asr.host-not-allowed", message:"..." }   // message 来自 BridgeError,不含用户语音
```
M5 telemetry pipeline 做采集时,`textLen` 可作为聚合维度(无 PII);任何上行通道(crashlytics / Sentry)的 breadcrumb 同规则。
