## 1. Overview

v3.4 Architecture Shifts Driving Bulk Deletes

FastAPI is gone. The entire `apps/api` Python process does not exist in v3.4; all runtime behaviour is implemented as TypeScript inside `apps/desktop/src/core/`. SQLAlchemy and Alembic are gone; all persistence is handled by Core Data in Swift. Python ASR (faster-whisper, PyAV) is permanently excluded per §A0. Sentry, cloud storage, and Python task scheduling are gone. The only surviving Python artefacts are the source files themselves, retained temporarily as a reference corpus for M5.2 porting.

Given this architecture, the triage policy is:

- **DELETE-redundant**: The agent/orchestrator logic has a functionally equivalent TS Vitest test already merged (M3.2.x, M3.3.x, M4.x). No new coverage is lost by removing the Python file.
- **DELETE-no-v34-target**: The test exercises a component that does not exist in v3.4 at all (FastAPI route, SQLAlchemy model, Alembic migration, Python ASR backend, Sentry, Python audio pipeline). There is no TS equivalent to port to.
- **KEEP-port**: The test exercises logic or a schema contract that exists in v3.4 but is NOT yet fully covered by any existing TS test. The Python test should be used as the authoritative specification for M5.2.x porting.
- **REWRITE**: No files qualify. No Python test was found where the TS implementation is sufficiently different to require re-authoring rather than straight porting. (The audio pipeline has no v3.4 equivalent at all, so it is DELETE-no-v34-target, not REWRITE.)

One important nuance: several L0 red-line lock tests in `agents/` are partially covered in TS but have unique edge cases or secondary assertions not yet in TS. Those files are marked KEEP-port with specific gap notes so M5.2 knows exactly what to add.

## 7. Deviations and Judgment Calls

### 7a. Test count drift: 471 → 366 (not 211)

The spec quoted "471 pytest" as the v3.3 baseline and the task context suggested 211 test functions across 68 files. Actual count via `grep -rE "^\s*(async )?def test_"` across all 68 files is **366 test functions**. The discrepancy from 471 is consistent with the fact that M5.1 surveys the v3.4 branch where some tests were already removed in prior milestones. The discrepancy from 211 is likely a miscounting in the task context (perhaps only counting `def test_` without `async def test_`). All 366 functions were triaged.

### 7b. No REWRITE verdicts

The spec anticipated ~50 REWRITE files. Inspection found zero cases where the v3.4 TS implementation is "materially different from Python" in a way that requires re-authoring rather than straight porting. The audio pipeline (formerly a REWRITE candidate) has no v3.4 target at all (Swift ASRGateway replaced it), making it DELETE-no-v34-target. The LLM gateway error mapping is a DELETE because the TS gateway is already tested in `llm.test.ts`. All schema tests port directly from Pydantic → Zod with minor syntactic translation.

### 7c. domain/test_coach_trigger.py marked DELETE-redundant

The 7 CoachService trigger tests (below-threshold, idempotent, failure-silent) are covered at graph level by `postReportGraph.contract.test.ts` + `postReportGraph.parallel.test.ts`. In v3.4 there is no `CoachService` Python class to port; the equivalent logic is in `core/graphs/postReportGraph.ts`. The graph-level tests are sufficient for the behaviour contracts. Marking DELETE-redundant rather than KEEP-port avoids inventing a TS service shim for test purposes only.

### 7d. domain/test_assets_text_extraction.py conditional

The verdict is KEEP-port pending a spot-check of `src/services/__tests__/pdf.test.ts`. If pdf.test.ts already covers raw-binary-not-leaked and corrupt-PDF fallback, this file can be downgraded to DELETE-redundant in M5.3. The tester notes the Python test explicitly calls out a production incident ("216k junk tokens") making the corrupt-PDF and binary-leak tests high value to retain.

### 7e. test_live_observation.py partial

Only the 2 prompt-template-content tests (lines 68–109) need porting. The 5 schema tests (lines 37–65) are redundant with `interviewerAgent.test.ts`. In M5.2.d, add 2 TS tests that assert the `core/agents/interviewer/prompts.ts` template string contains "≤ 30 字", "教学语气", and the 3 don't-examples.

### 7f. §A0 Python sidecar exclusion drives bulk deletes

Per v3.4 grand architecture §A0: Tauri, Python sidecar, faster-whisper, PyAV, and disable-library-validation entitlements are permanently excluded for Mac App Store compliance. This single constraint accounts for all 21 DELETE-no-v34-target files in infra/, e2e/, migrations/, root test_*.py, and the orchestrator audio/ASR tests. §A0 is the primary driver; the secondary driver is that FastAPI is gone, which accounts for all 8 api/* files.
