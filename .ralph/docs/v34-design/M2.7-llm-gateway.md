### 2.3 决策:URLSession 层冗余 hostname check —— **必须冗余**

ATS 已经在系统层把非白名单 host 拦掉,但 LLMGateway 在 Swift 代码层 **再做一次 hostname 白名单 check**,**作为冗余防御**。

**为什么要冗余而不是省略:**

1. **多层防御原则(defense-in-depth)**:ATS 只检查 TLS 握手时的 host,不阻止 URL 构造时被错误参数注入(例如未来某 PR 把 `endpoint` 改成可配置变量,ATS 仍会因 Info.plist 限制阻断,但代码层若提前拒绝可在单元测试就发现 bug,而不是运行时白屏)
2. **错误码语义更准确**:ATS 失败的 NSURLError 是 -1003 / -1004 等系统码,而代码层显式 check 可以返回 `llm.host-not-allowed`,与其它 `llm.*` 错误码体系一致,便于日志排查与用户文案
3. **测试可控**:XCTest 用 URLProtocol mock 跑非白名单 host 时,ATS 不参与(URLProtocol 拦在 ATS 之前),只有代码层 check 能触发该路径覆盖,测试矩阵完整
4. **commit message 容易出问题**:有些团队成员可能把 ark host 复制粘贴时多一个空格或大小写不规范,代码层 lower-case 对比可以早早抛错

**实施位置**:`LLMGateway.makeRequest(_:)` 入口处:

```swift
private static let allowedHost = "ark.cn-beijing.volces.com"

private func makeRequest(...) throws -> URLRequest {
    let url = URL(string: Self.endpoint)!
    guard url.host?.lowercased() == Self.allowedHost else {
        throw BridgeError(code: "llm.host-not-allowed",
                          message: "host '\(url.host ?? "")' not in allow list")
    }
    // ... continue building request
}
```

**反例(本设计拒绝)**:

```swift
// ❌ "ATS 已经把关了,代码不查 host" — 没有错误码语义、单元测试无法在 mock URLProtocol 下覆盖
let url = URL(string: providerConfig.endpoint)!  // 任何 endpoint 字符串注入都通过
```

## §3 Authorization 注入 + ARK_API_KEY 生命周期

### 3.1 生命周期序列图(ASCII)

```
+--------+    1. read("ark-api-key")    +--------+
|LLMGate |  ------------------------->  |Keychain|     # Swift in-process,never crosses Bridge
|  way   |  <-------------------------  |Service |
+--------+    2. Data? (utf8 bytes)     +--------+
    |
    | 3. let apiKey = String(data:..., encoding: .utf8)   # stack-local
    |    guard !apiKey.isEmpty
    v
+--------+   4. URLRequest.setValue("Bearer \(apiKey)", forHTTPHeaderField: "Authorization")
|URLReq  |
+--------+
    |
    | 5. URLSession.shared.data(for: request)             # TLS handshake, ATS check, send body
    v
+--------+   6. response, body
| ARK    |
+--------+
    |
    | 7. function returns; Swift ARC drops apiKey String, URLRequest, response
    v
+-------------------------------------+
| ARC release: zero secret in memory  |
+-------------------------------------+

Throughout: NEVER log apiKey, NEVER write to file, NEVER cross Bridge boundary.
```

**关键不变量**:

- 任何函数返回前 apiKey 必须是 stack-local;**绝不**写入 instance property、static、UserDefaults、SQLite、log
- `URLRequest.allHTTPHeaderFields["Authorization"]` 在 task 完成后随 URLSessionTask 一起释放
- 连续两次 LLM 调用之间 Swift 内存中应该没有 ARK_API_KEY 的拷贝(即每次调用都重读 Keychain;Keychain `SecItemCopyMatching` 性能足够,~1ms / call)

### 3.2 调用点伪代码(供 M2.7.dev 直接抄)

```swift
final class LLMGateway {
    private let keychain: KeychainService
    private static let endpoint = "https://ark.cn-beijing.volces.com/api/v3/chat/completions"
    private static let allowedHost = "ark.cn-beijing.volces.com"

    init(keychain: KeychainService) {
        self.keychain = keychain
    }

    /// Build URLRequest with Authorization injected. Caller MUST consume request immediately.
    private func makeRequest(body: Data, accept: String) throws -> URLRequest {
        // §A0.4: read Keychain → stack-local String → header → release on return
        let apiKeyData = try keychain.read(account: "ark-api-key")
        guard let data = apiKeyData,
              let apiKey = String(data: data, encoding: .utf8),
              !apiKey.isEmpty else {
            throw BridgeError(code: "llm.api-key-missing",
                              message: "ark-api-key not configured in Keychain")
        }

        let url = URL(string: Self.endpoint)!
        guard url.host?.lowercased() == Self.allowedHost else {
            throw BridgeError(code: "llm.host-not-allowed",
                              message: "host '\(url.host ?? "")' not in allow list")
        }

        var req = URLRequest(url: url)
        req.httpMethod = "POST"
        req.setValue("Bearer \(apiKey)", forHTTPHeaderField: "Authorization")
        req.setValue("application/json", forHTTPHeaderField: "Content-Type")
        req.setValue(accept, forHTTPHeaderField: "Accept")
        req.httpBody = body
        // apiKey String goes out of scope at function return → ARC release
        return req
    }
}
```

### 3.3 禁日志规则(具体 SOP + grep pattern)

**铁律**:任何 `os_log` / `print` / `NSLog` / `console.log` 涉及 LLM 调用的输出 **必须 redact** Authorization header 与请求 body 中的 messages 内容(messages 可能含简历 PII)。

**允许日志**:

- HTTP method + URL(URL 不含 query secret)
- HTTP status code
- 重试次数 / 退避 ms
- BridgeError code(永远是机器读字符串,如 `llm.rate-limited`)
- 响应 `usage.totalTokens`(数字,不含原文)

**禁止日志**:

- `request.allHTTPHeaderFields`(字典里 Authorization 在裸字符串里)
- `request.httpBody` 原始或 base64
- `String(data: bodyData, encoding: .utf8)`
- 任何 `apiKey` / `bearer` / `Authorization` 变量字面量

**Pre-commit grep SOP**(M2.7.dev 实施时加到 `scripts/check-no-key-leak.sh`,本 doc 锁规则,M2.7.dev 落地脚本):

```bash
# Banned patterns in apps/macos/**/*.swift:
grep -rE "os_log.*[Aa]uthorization" apps/macos/ && exit 1
grep -rE "print.*[Bb]earer" apps/macos/ && exit 1
grep -rE "print.*allHTTPHeaderFields" apps/macos/ && exit 1
grep -rE "print.*[Aa]pi[Kk]ey" apps/macos/ && exit 1

# Banned patterns in apps/desktop/src/**/*.ts:

```

## §4 Codable 模型(Swift)+ Zod 模型(JS)

### 4.1 双端对照表

| Swift Codable struct | JS Zod schema | 说明 |
|---|---|---|
| `ChatMessage` | `ChatMessageSchema` | `role` ∈ `"system" / "user" / "assistant" / "tool"`;`content: String?`;`name: String?`;`tool_call_id: String?`;`tool_calls: [ToolCall]?` |
| `ResponseFormat` | `ResponseFormatSchema` | `{ type: "json_object" }`(目前只支持 OpenAI compat 的两种 type:`text` / `json_object`) |
| `ToolDef` | `ToolDefSchema` | `{ type: "function", function: { name, description, parameters: JSONSchema } }` |
| `ToolChoice` | `ToolChoiceSchema` | `"auto" / "none"` 字符串 OR `{ type: "function", function: { name } }` |
| `ChatCompletionRequest` | `ChatCompletionRequestSchema` | 同步 + 流式共用,`stream: Bool` 区分 |
| `ChatChoice` | `ChatChoiceSchema` | `index: Int` / `message: ChatMessage` / `finish_reason: String` |
| `Usage` | `UsageSchema` | `prompt_tokens / completion_tokens / total_tokens`(都是 Int) |
| `ChatCompletionResponse` | `ChatCompletionResponseSchema` | `id / object / created / model / choices: [ChatChoice] / usage: Usage` |
| `ChatChunkDelta` | `ChatChunkDeltaSchema` | SSE delta:`{ role?, content?, tool_calls? }` |
| `ChatChunkChoice` | `ChatChunkChoiceSchema` | `{ index, delta: ChatChunkDelta, finish_reason: String? }` |
| `ChatChunk` | `ChatChunkSchema` | SSE 单帧:`{ id, choices: [ChatChunkChoice], usage?: Usage }` |
| `ToolCall` | `ToolCallSchema` | `{ id, type: "function", function: { name, arguments: String (JSON-encoded) } }` |

> **CodingKeys 注**:Swift 端用 snake_case CodingKey 映射(`finish_reason` 等)以与 OpenAI compat 协议字段对齐;Bridge 边界 method `llm.chat` 的 result 字段则统一 camelCase(详见 §7)。

> **决策:JS 端字段 snake_case 还是 camelCase?** 选 **snake_case**(与 ARK 上行 body 一致),理由:
> 1. Bridge `llm.chat` params 直接透传到 Swift,Swift 同样 snake_case decode,**减少一道字段映射**;

## §5 同步 chat (`llm.chat`)

### 5.1 函数签名

```swift
extension LLMGateway {
    /// Synchronous chat (stream=false). Decodes full response in one shot.
    func chat(_ params: ChatCompletionRequest) async throws -> ChatCompletionResponse {
        var p = params
        p.stream = false  // force sync
        let body = try JSONEncoder().encode(p)
        let req = try makeRequest(body: body, accept: "application/json")
        let (data, resp) = try await retryingURLSession(req)
        let http = resp as! HTTPURLResponse
        try mapHTTPError(status: http.statusCode, data: data)
        do {
            return try JSONDecoder().decode(ChatCompletionResponse.self, from: data)
        } catch {
            throw BridgeError(code: "llm.decode-failed",
                              message: "response decode failed: \(error)")
        }
    }
}
```

### 5.2 Bridge method 注册

```swift
// 在 WebViewController.registerLLMHandlers() 内
bridgeRouter.register(method: "llm.chat") { [weak self] (p: ChatCompletionRequest) -> LLMChatResult in
    guard let self = self else {
        throw BridgeError(code: "bridge.internal-error", message: "service released")
    }
    let resp = try await self.llmGateway.chat(p)
    let first = resp.choices.first
    return LLMChatResult(
        content: first?.message.content,
        toolCalls: first?.message.toolCalls,
        finishReason: first?.finishReason ?? "stop",
        usage: resp.usage
    )
}
```

`LLMChatResult` 是 Bridge 边界 result(camelCase),与 ARK 原始 response 解耦,UI 拿到的是已经 camelCase 化的数据。

### 5.3 重试策略(指数退避 ×3)

| HTTP status | 行为 |
|---|---|
| 200 | success,decode body |
| 401 | **不重试**,抛 `llm.api-key-invalid` |
| 4xx(其它) | **不重试**,抛 `llm.http-4xx`(message 含 status + ARK error.code) |
| 429 | 重试 |
| 500 / 502 / 503 / 504 | 重试 |
| 5xx(其它) | 重试 |
| 网络中断(NSURLError) | 重试 |

退避序列:`0.5s → 1.0s → 2.0s`,**最多 3 次重试**(共 4 次请求)。3 次后抛 `llm.http-5xx-retry-exhausted` 或 `llm.network-error`。

```swift
private func retryingURLSession(_ req: URLRequest) async throws -> (Data, URLResponse) {
    let backoffMs: [UInt64] = [500, 1000, 2000]  // 3 retries
    var lastError: Error?
    for attempt in 0..<(backoffMs.count + 1) {
        do {
            let (data, resp) = try await URLSession.shared.data(for: req)
            let status = (resp as? HTTPURLResponse)?.statusCode ?? 0
            if shouldRetry(status: status), attempt < backoffMs.count {
                try await Task.sleep(nanoseconds: backoffMs[attempt] * 1_000_000)
                continue
            }
            return (data, resp)
        } catch {
            lastError = error
            if attempt < backoffMs.count {
                try await Task.sleep(nanoseconds: backoffMs[attempt] * 1_000_000)
                continue
            }
            throw BridgeError(code: "llm.network-error",
                              message: "\(error)")
        }
    }
    throw BridgeError(code: "llm.http-5xx-retry-exhausted",
                      message: "\(lastError?.localizedDescription ?? "unknown")")
}

private func shouldRetry(status: Int) -> Bool {
    return status == 429 || (status >= 500 && status < 600)
}
```

### 5.4 错误码映射(`mapHTTPError`)

| Status | BridgeError code |
|---|---|
| 401 | `llm.api-key-invalid` |
| 403 | `llm.api-key-invalid`(部分 ARK 部署用 403 表达 key 错) |
| 429 | `llm.rate-limited`(在所有重试耗尽后) |
| 400 / 422 | `llm.params-invalid`(message 含 ARK error.code 如 `context_length_exceeded`) |
| 5xx 重试耗尽 | `llm.http-5xx-retry-exhausted` |
| 其它 4xx | `llm.http-4xx` |

```swift
private func mapHTTPError(status: Int, data: Data) throws {
    if (200..<300).contains(status) { return }
    let arkErr = (try? JSONDecoder().decode(ARKErrorEnvelope.self, from: data))?.error
    let detail = arkErr.map { "[\($0.code ?? "?")] \($0.message ?? "")" } ?? "status \(status)"
    switch status {
    case 401, 403: throw BridgeError(code: "llm.api-key-invalid", message: detail)
    case 429: throw BridgeError(code: "llm.rate-limited", message: detail)
    case 400, 422: throw BridgeError(code: "llm.params-invalid", message: detail)
    case 500..<600: throw BridgeError(code: "llm.http-5xx-retry-exhausted", message: detail)
    default: throw BridgeError(code: "llm.http-4xx", message: detail)
    }
}
```

### 6.2 URLSession `bytes(for:)` 行迭代解析

```swift
extension LLMGateway {
    /// Streaming chat. Pushes each chunk via BridgeRouter.dispatchEvent.
    func chatStream(
        _ params: ChatCompletionRequest,
        streamId: String,
        router: BridgeRouter
    ) async {
        do {
            var p = params
            p.stream = true
            let body = try JSONEncoder().encode(p)
            let req = try makeRequest(body: body, accept: "text/event-stream")

            let (bytes, resp) = try await URLSession.shared.bytes(for: req)
            let http = resp as! HTTPURLResponse
            if !(200..<300).contains(http.statusCode) {
                // Drain body for error detail
                var data = Data()
                for try await b in bytes { data.append(b) }
                try mapHTTPError(status: http.statusCode, data: data)
                return
            }

            for try await line in bytes.lines {
                try Task.checkCancellation()
                guard line.hasPrefix("data: ") else { continue }
                let payload = String(line.dropFirst(6))
                if payload == "[DONE]" {
                    router.dispatchEvent(type: "stream-end",
                                        streamId: streamId,
                                        payload: ["finishReason": "stop"])
                    return
                }
                guard let chunkData = payload.data(using: .utf8),
                      let chunk = try? JSONDecoder().decode(ChatChunk.self, from: chunkData)
                else { continue }   // skip malformed line; log code only, never content
                let choice = chunk.choices.first
                let delta = choice?.delta.content ?? ""
                router.dispatchEvent(type: "stream-chunk",
                                     streamId: streamId,
                                     payload: ["content": delta])
                if let reason = choice?.finishReason, !reason.isEmpty {
                    router.dispatchEvent(type: "stream-end",
                                         streamId: streamId,
                                         payload: ["finishReason": reason])
                    return
                }
            }
            // Stream ended without [DONE] — emit stream-end with reason "eof"
            router.dispatchEvent(type: "stream-end",
                                 streamId: streamId,
                                 payload: ["finishReason": "eof"])
        } catch is CancellationError {
            router.dispatchEvent(type: "stream-error",
                                 streamId: streamId,
                                 payload: ["code": "llm.stream-cancelled",
                                           "message": "task cancelled"])
        } catch let bridgeErr as BridgeError {
            router.dispatchEvent(type: "stream-error",
                                 streamId: streamId,
                                 payload: ["code": bridgeErr.code,
                                           "message": bridgeErr.message])
        } catch {
            router.dispatchEvent(type: "stream-error",
                                 streamId: streamId,
                                 payload: ["code": "llm.stream-failed",
                                           "message": "\(error)"])
        }
    }
}
```

### 6.3 取消(Task.cancel)

`llm.chatStream` 由 JS 端通过 **新的 control method** `llm.stopStream({ streamId })` 触发取消。Swift 侧维持 `[String: Task]` 字典,收到 stop 时 `task.cancel()` → `for try await` 抛 `CancellationError` → emit `stream-error` with code `llm.stream-cancelled`。

```swift
private var activeStreams: [String: Task<Void, Never>] = [:]

bridgeRouter.register(method: "llm.chatStream") { (p: LLMChatStreamParams) -> LLMChatStreamStarted in
    let task = Task {
        await self.llmGateway.chatStream(p.request, streamId: p.streamId, router: self.bridgeRouter)
        self.activeStreams[p.streamId] = nil
    }
    self.activeStreams[p.streamId] = task
    return LLMChatStreamStarted(streamId: p.streamId, started: true)
}

bridgeRouter.register(method: "llm.stopStream") { (p: StreamIdParams) -> EmptyResponse in
    self.activeStreams[p.streamId]?.cancel()
    self.activeStreams[p.streamId] = nil
    return EmptyResponse()
}
```

> **决策:为什么新增 `llm.stopStream` 而不是复用 M2.1 §7.2 提的 `AbortController` 思路?**
> M2.1 §7.2 当时把取消推给"JS fetch 级别 AbortController",但本 v3.4 架构 JS **不直连** ARK(走 Bridge),JS 没有可取消的 fetch 句柄。最干净的办法是 Bridge 显式新增 stop method,与 `audio.stop` / `asr.stop` 体系一致。**M2.1 §7.2 留下的"M2.6.dev 实现"占位由本设计兑现**,M2.7.dev 实施时同 commit 在 M2.1 design doc §12 加一行追溯说明(若该 doc 是 protected,则只在本 doc + commit body 留痕)。

> **决策:为什么用 Vercel AI SDK v4 而不是手写 useChat / 直接用 EventSource?**
> 1. AI SDK 已抽象好 `useChat` / `useCompletion` React hook,对接 React UI(M3.4)零自定义代码;
> 2. v4 版的 `streamText` / `generateText` API 与 OpenAI compat schema 一致,我们 ARK 上行 body 也是 OpenAI compat,字段对齐天然顺;
> 3. AI SDK 期待的输入是 ReadableStream<Uint8Array> with SSE-formatted bytes,我们用 `createDataStream` adapter 把 BridgeEvent 转成这种流即可,**不与上层 React 耦合**;
> 4. 反例:**手写 useChat hook** 会让 M3.4 重做轮子,且 function-calling / tool-call delta 协议变化时维护成本高;**直接用 EventSource** 不可行,因为 EventSource 只能从 HTTP 拉数据,我们的源是 Bridge event。

### 8.2 `createDataStream(streamId)` adapter

`apps/desktop/src/services/llm.ts`(M2.7.dev 新建):

```ts
import { bridge, BridgeEvent } from "./nativeBridge";
import { StreamChunkPayloadSchema, StreamEndPayloadSchema, StreamErrorPayloadSchema }
  from "./nativeBridge.schemas";

/**
 * Convert BridgeEvent stream-chunk/stream-end/stream-error events
 * into a ReadableStream<Uint8Array> in OpenAI-compatible SSE wire format,
 * suitable for Vercel AI SDK's streamText / useChat consumers.
 *
 * §C3: this adapter never touches Authorization or apiKey.
 */
export function createDataStream(streamId: string): ReadableStream<Uint8Array> {
  const enc = new TextEncoder();
  return new ReadableStream<Uint8Array>({
    start(controller) {
      const off1 = bridge.on("stream-chunk", (e) => {
        if (e.streamId !== streamId) return;
        const payload = StreamChunkPayloadSchema.parse(e.payload);
        const sse = `data: ${JSON.stringify({
          choices: [{ delta: { content: payload.content } }],
        })}\n\n`;
        controller.enqueue(enc.encode(sse));
      });
      const off2 = bridge.on("stream-end", (e) => {
        if (e.streamId !== streamId) return;
        const payload = StreamEndPayloadSchema.parse(e.payload);
        const finish = `data: ${JSON.stringify({
          choices: [{ delta: {}, finish_reason: payload.finishReason }],
          usage: payload.usage,
        })}\n\n`;
        controller.enqueue(enc.encode(finish));
        controller.enqueue(enc.encode("data: [DONE]\n\n"));
        controller.close();
        off1(); off2(); off3();
      });
      const off3 = bridge.on("stream-error", (e) => {
        if (e.streamId !== streamId) return;
        const payload = StreamErrorPayloadSchema.parse(e.payload);
        controller.error(new Error(`[${payload.code}] ${payload.message}`));
        off1(); off2(); off3();
      });
    },
    async cancel() {
      try {
        await bridge.call("llm.stopStream", { streamId });
      } catch { /* swallow — cancel is best-effort */ }
    },
  });
}
```

## §9 反模式拒绝清单(显式回引 §K)

本设计 **明确拒绝** 以下做法。M2.7.dev 实施过程中如有 subagent / contributor 提议任一条,**当场拒绝并报告**。

### ❌ 反模式 1: 把 ARK_API_KEY 通过 messageHandler 传给 JS 临时存内存(§K #6 直击)

> 提议:"为节省 Bridge 调用次数,JS 启动时 `bridge.call('keychain.read', {account:'ark-api-key'})` 拉一次缓存到 `window` 全局,此后每次 LLM 调用 JS 直接拼 Authorization 头。"

**拒绝**:
1. JS 内存对 sandbox 外的 attacker 视作可读(WebKit JIT、devtools、远程 XSS via 第三方依赖供应链);Keychain `kSecAttrAccessibleAfterFirstUnlock` 提供的 OS 级保护一旦"过桥"立即失效
2. `keychain.read` Bridge method **从未注册**(M2.2 故意只暴露 save/exists/delete,见 KeychainService.swift line 40 注释)
3. Bridge 调用次数不是瓶颈:Swift LLMGateway 内部直读 Keychain ~1ms / call,远小于 ARK 网络 round-trip
4. App Store review 历史记录:任何把 API key 持久化到 WebView storage / `localStorage` / IndexedDB 的设计有被拒先例(Guideline 5.1.1 / 5.1.2)

### ❌ 反模式 2: 用 OpenAI proxy 服务端绕过用户 BYOK key

> 提议:"在我们自己的服务器上跑一个 OpenAI / ARK proxy,给客户端发短期 token,简化用户配置。"

**拒绝**:
1. v3.4 商业模式锁 BYOK(Bring Your Own Key,用户自己的 ARK key 直连火山),不是 SaaS proxy 模型
2. 引入服务端 = 引入新 attack surface + 我们承担 ARK 调用费
3. 与§A0 总纲冲突:任何 host 都不在白名单(我们的 API server domain 没在 Info.plist NSExceptionDomains)
4. 与 §A0.4 冲突:proxy 本质是把用户 key 集中托管,违反"key 仅出现在用户本机 Keychain"规则

### ❌ 反模式 3: 为减小复杂度,只支持 chat 不支持 chatStream

> 提议:"先做 `llm.chat`,UI 全等待整段返回,M2.7.dev 提速;chatStream 留给 M3.x。"

**拒绝**:
1. PRD §6.6 锁"边说边出字"用户体验,首字延迟 < 1.5s(同步模式整段返回 P50 通常 5-15s,体验灾难)
2. F-402 acceptance 明确要求流式
3. SSE 解析 + BridgeEvent 接驳本身工程量不大(本 doc §6 已锁所有协议),延后只会让 M3.x 重新挖坑

### ❌ 反模式 4: 临时关 ATS / 加 disable-library-validation 调试

> 提议:"调试 ARK 自定义部署 endpoint 时,暂时 NSAllowsArbitraryLoads=true 让 dev 跑通。"

**拒绝**:
1. §A0.2 锁死 entitlement 黑名单,disable-library-validation 是禁项
2. ATS 关一次就再也关不回来(commit history 可见,App Store reviewer 会注意)
3. Dev 环境真要测自定义 endpoint:在 Info.plist NSExceptionDomains 加临时 host,但**绝不**开 NSAllowsArbitraryLoads;M2.7.dev acceptance 默认锁死 ark.cn-beijing.volces.com

### ❌ 反模式 5: 用 `os_log .public` 输出 Authorization header 来调试 401

> 提议:"401 报错查不出来,临时把 request.allHTTPHeaderFields 打到 os_log,review 完再删。"

**拒绝**:
1. §A0.4 红线;一旦 commit 进 git,key 就泄漏(即使后续 commit 删除也留在 history)
2. macOS 上 os_log .public 在 Console.app 持久,被任何登录用户读到
3. 调试 401 应当用 mock URLProtocol 单测覆盖,**不**靠生产代码 print
