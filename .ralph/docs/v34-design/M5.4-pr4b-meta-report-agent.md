### 2.2 关键 Python decisions(继承到 TS)

1. **触发门槛 ≥ 1**(注意:**用户上下文写 ≥3 是错误的**,Python `_load_eligible_sessions` 仅 raise 400 when 0 — 见 `domain/meta_reports/service.py:47-51` `_EMPTY_REPORTS_DETAIL = "至少需要 1 场已完成的面试"`)。N=1 降级在 prompt 里显式约定:`recurring_weaknesses=[]` / `improvement_signals=[]` / 切单场叙述口吻。
2. **聚合范围**:用户的所有 `InterviewSession` ⨝ `InterviewReport WHERE status=READY`,**无 30 天 / N 限制**。如果 `request.session_ids` 给定,过滤为该子集;否则全用。
3. **排序**:`session.created_at ASC`(prompt 假定时间升序,trend 逻辑直接消费)。
4. **idempotency**:**无 dedup**。每次 trigger 创建新 `meta_reports` 行(覆盖快照存于 `covered_session_ids` JSON 字段)。
5. **状态机**:`generating` → `ready` | `failed`。LLMError → 写 `payload={detail: str}` + `status=failed`。
6. **异步 vs 同步**:Python 走 `task_queue.enqueue` 后台跑,接口立即 202 + `status=generating`。详见 §6.5 v3.4 同步选择。
7. **payload schema**:`status=ready` 时 `payload = MetaReportOutput.model_dump(mode="json")`;`status=failed` 时 `payload = {detail: "..."}`。shared-types 的 `MetaReportPayload | MetaReportFailurePayload | null` 已 mirror。
8. **prompt 风格**:中文,口吻"教练第二人称'你'",`aspect 复用源 reasons[].aspect`,`evidence_quotes 必须是源 reasons[].quote 真实片段,不得编造`。

### 2.3 与本 TS port 不一致的 Python 假设(需主动处理)

- **Python `MetaReportAgentInput.sessions[].config_snapshot: dict / report_payload: dict`** = "塞整 dict 进 prompt"。TS 我们拿到的是从 SQLite 读出的 stringified JSON 列。**统一为 string-typed input**,prompt 端不解 JSON,直接拼;agent input zod schema 用 `z.string()`(JSON-stringified)而不是 `z.record()`。这避免在 input 边界做 JSON.parse 和重新 stringify 的浪费,也减小 schema PII 攻击面(`z.record(z.unknown())` 漏光)。详见 §3.1 字段决策。
- **Python `task_queue.enqueue`**:v3.4 无 task_queue,改同步 await,与 PR3b2 generateReport 一致。详见 §6.5。

## §3 TS schema 设计

### 3.1 文件:`src/core/schemas/meta-report.ts`(NEW,~110 LOC)

注意命名:**新文件 `meta-report.ts`(单数 + dash)** 持 agent zod schema;现有 `meta_reports.ts`(复数 + underscore)持 HTTP I/O zod schema(已存在,3 axios 函数已用)。两者职责不同,**不合并** — agent schema 内部细化字段(N≥2 / verdict-tier-非倒退 / aspect 字符串约束),HTTP I/O schema 对外保持宽松(`payload: z.record(z.unknown())` 兼容 generating/ready/failed 三态)。

```ts
import { z } from "zod";

// ===== L0 lock — 4-tier verdict (与 shared-types MetaReportVerdict 一致) =====
export const MetaReportVerdictSchema = z.enum(["weak", "mixed", "solid", "strong"]);
export type MetaReportVerdict = z.infer<typeof MetaReportVerdictSchema>;

const VERDICT_RANK: Record<MetaReportVerdict, number> = {
  weak: 0, mixed: 1, solid: 2, strong: 3,
};

// ===== Input — strict() PII guard =====
// Python: MetaReportSessionInput { session_id, session_created_at(datetime),
//          config_snapshot(dict), report_payload(dict) }
// TS 决策:config_snapshot / report_payload 为 string(JSON-stringified) 而非 record,
// 因为 (a) 我们从 SQLite TEXT 列读取,(b) prompt 直接拼字符串,(c) 减小 PII 攻击面。
export const MetaReportAgentSessionInputSchema = z
  .object({
    session_id: z.string().min(1),
    // ISO8601 — Python 用 datetime,序列化成 ISO 字符串
    session_created_at: z.string().datetime(),
    // JSON-stringified config snapshot;调用侧已 JSON.stringify
    config_snapshot_json: z.string(),
    // JSON-stringified ReportAgentOutput;调用侧从 interview_reports.payload 直读
    report_payload_json: z.string(),
  })
  .strict();
export type MetaReportAgentSessionInput = z.infer<typeof MetaReportAgentSessionInputSchema>;

export const MetaReportAgentInputSchema = z
  .object({
    sessions: z.array(MetaReportAgentSessionInputSchema).min(1),
  })
  .strict();
export type MetaReportAgentInput = z.infer<typeof MetaReportAgentInputSchema>;

// ===== Output — strict(),与 shared-types MetaReportPayload 字段对齐 =====
export const RecurringWeaknessSchema = z
  .object({
    aspect: z.string().min(1),
    occurrence_count: z.number().int().min(2),  // Python: ge=2
    session_ids: z.array(z.string().min(1)).min(1),
    evidence_quotes: z.array(z.string()),
  })
  .strict();

export const ImprovementSignalSchema = z
  .object({
    aspect: z.string().min(1),
    from_verdict: MetaReportVerdictSchema,
    to_verdict: MetaReportVerdictSchema,
    earlier_session_id: z.string().min(1),
    later_session_id: z.string().min(1),
  })
  .strict()
  // 4-tier rank 严格递进 — prompt 已禁倒退;schema 兜底
  .refine((s) => VERDICT_RANK[s.to_verdict] > VERDICT_RANK[s.from_verdict], {
    message: "improvement_signals.to_verdict must rank > from_verdict",
  });

export const PassProbabilityPointSchema = z
  .object({
    session_id: z.string().min(1),
    session_created_at: z.string().datetime(),
    pass_probability: z.number().int().min(0).max(100),
  })
  .strict();

export const NextFocusAreaSchema = z
  .object({
    aspect: z.string().min(1),
    reason: z.string().min(1),
    suggested_prep: z.string().min(1),
  })
  .strict();

export const MetaReportAgentOutputSchema = z
  .object({
    overall_trend_summary: z.string().min(1),
    recurring_weaknesses: z.array(RecurringWeaknessSchema),
    improvement_signals: z.array(ImprovementSignalSchema),
    pass_probability_series: z.array(PassProbabilityPointSchema),
    next_focus_areas: z.array(NextFocusAreaSchema),
  })
  .strict();
export type MetaReportAgentOutput = z.infer<typeof MetaReportAgentOutputSchema>;
```

### 3.2 与 shared-types 差异 + 处置

| 字段 | shared-types | meta-report.ts schema | 差异 / 处置 |
|---|---|---|---|
| `MetaReportVerdict` | `"weak"\|"mixed"\|"solid"\|"strong"` | 一致 | ✅ 直接复用语义 |
| `RecurringWeakness.occurrence_count` | `number` | `z.number().int().min(2)` | schema 加严(N≥2),contract 兼容 |
| `ImprovementSignal` rank check | 无 | `.refine(rank递进)` | schema 加严,output 类型仍是 `{from_verdict, to_verdict}` |
| `PassProbabilityPoint.pass_probability` | `number` | `z.number().int().min(0).max(100)` | schema 加严 |
| `MetaReportPayload` | TS type | = `MetaReportAgentOutput`(同字段) | 二者字段同名同义,zod schema 是更严的子集 |
| `MetaReportFailurePayload` | `{ detail: string }` | 不在 agent schema(只在 HTTP I/O 层) | agent 层不出 failure;失败由 api/metaReports.ts 写 `{detail}` 进 DB |

→ 出 agent 时 `MetaReportAgentOutput` 直接 stringify 进 `meta_reports.payload`;UI 通过 `MetaReportDetailResponse.payload` 拿到的 union 类型与 shared-types `MetaReportPayload` 兼容,**零 UI 改动**。

### 3.3 PII-safe 检查(逐字段)

| 字段 | PII 风险 | 处置 |
|---|---|---|
| `session_id` / UUID | 低(随机串,无 PII) | ✅ |
| `session_created_at` | 低(时间戳,无 PII) | ✅ |
| `config_snapshot_json` | 含岗位 / direction(已 PII-safe by upstream — `interview_configs` 表本身不存简历原文) | ✅(职级 / 风格 / 时长) |
| `report_payload_json` | 含 `ai_verdict` / `summary` / `reasons[].quote`,**不含简历原文 / 邮箱 / 手机**(`runReportAgent` 已 sanitize,且 input 不含原文) | ✅ |
| Output 字段 | 都是 trend 摘要,不应携 PII;**prompt 显式禁** | ✅ |

agent input 的 `.strict()` 是 §A11 第 1 层防线;prompt 是第 2 层;运行时 `MetaReportAgentInputSchema.parse(input)` 在 LLM call 前抛 ZodError(PR3 同 pattern)。

### 4.2 L0 锁交互检查(产出全 verdict / aspect / score)

| L0 锁 | 是否触碰 | 处置 |

| 3 档 PassLikelihood(中上 / 中 / 中下) | 不触碰(MetaReport 用 `pass_probability_series` 数值,不输出 `pass_likelihood`) | ✅ 隔离 |

| 7 fillerWords | 不触碰(filler 是 turn 级别) | ✅ |
| 4 personas | 不触碰 | ✅ |

### 4.3 verdict 4-tier 与 PassLikelihood 3-tier 的关系

二者**不互转**,各自独立:
- `PassLikelihood`(中上 / 中 / 中下)— ReportAgent 出,**单场**胜率档位,UI 用色块 + 标签
- `MetaReportVerdict`(weak/mixed/solid/strong)— MetaReportAgent 出,**单 aspect** 在某场的强度,trend 比较用
- `pass_probability_series`(0-100 int)— MetaReportAgent 输出,数值直接 copy from `report_payload.pass_probability`,**不重新计算**

prompt §4.1 显式约束:数值直接取自源报告,不二次计算 → 防 LLM 幻觉。

## §5 跨 session aggregation 策略

### 5.1 数据源 — 读哪些表

| 表 | 字段 | 用途 |
|---|---|---|
| `interview_sessions` | `id, user_id, status, created_at, config_snapshot` | 谁的 session、什么时候、用什么 config |
| `interview_reports` | `session_id, status, payload` | ReportAgentOutput,只取 `status='ready'` 的 |

JOIN by `interview_reports.session_id = interview_sessions.id`,user_id = "local"。

### 5.2 N 与 date range filter

| 维度 | Python 语义 | TS port 决策 |
|---|---|---|
| 最小 N | ≥ 1(`_EMPTY_REPORTS_DETAIL = "至少需要 1 场"`) | **沿用 ≥ 1**,prompt N=1 降级规则承担。 |
| 最大 N | 无限制(全用) | **沿用无限制**;但 §5.3 推荐加上 ceiling。 |
| date range | 无 filter | **沿用无 filter**;按 `created_at ASC` 排序。 |
| status filter | 仅 `interview_reports.status='ready'` | **沿用** |

### 5.3 性能 ceiling 推荐(non-blocker)

LLM input token 估算:每场 report payload(JSON dump)~ 2-4 KB → 50 场 ≈ 200 KB。doubao-seed-1-6 上下文 32K-128K,实际 50 场已挤;但 v3.4 用户最多面试 10-30 场量级。

**决策**:本 PR4b.dev **不加 ceiling**(沿用 Python 行为);只在 prompt 里写 "按 created_at 升序"。如果未来 user 反馈 OOM / token 超限,加 N≤30 ceiling(取最近 30 场)— 标 v3.5 backlog。**不在本 PR scope**。

### 5.4 输入数据 SQL(伪代码)

```sql
-- 全量(request.session_ids 未给定)
SELECT
  s.id              AS session_id,
  s.created_at      AS session_created_at,
  s.config_snapshot AS config_snapshot_json,  -- TEXT,SQLite 直存 JSON
  r.payload         AS report_payload_json    -- TEXT
FROM interview_sessions s
JOIN interview_reports r ON r.session_id = s.id
WHERE s.user_id = ?                            -- "local"
  AND r.status = 'ready'
ORDER BY s.created_at ASC;

-- 子集(request.session_ids 给定)
-- 同上,加 AND s.id IN (?, ?, ...)
```

**TS 实现注**:用 `db.query` 拿 rows,再 `.map` 成 `MetaReportAgentSessionInput[]`。SQLite `IN (?, ?)` 占位符按数组长度动态构造;参数全部走 prepared statement bind values(防注入)。

  MetaReportAgentInputSchema,
  MetaReportAgentOutputSchema,
  type MetaReportAgentInput,
  type MetaReportAgentOutput,
} from "@/core/schemas/meta-report";
import type { LLMProvider, Message } from "@/core/llm/types";
import { systemPrompt, userPrompt } from "./prompts";

export interface MetaReportAgentDeps {
  llm: LLMProvider;
}

export async function runMetaReportAgent(
  input: MetaReportAgentInput,
  deps: MetaReportAgentDeps,
): Promise<MetaReportAgentOutput> {
  // §A11 layer 1 — strict() rejects unknown fields BEFORE LLM call
  const validated = MetaReportAgentInputSchema.parse(input);

  const messages: Message[] = [
    { role: "system", content: systemPrompt(validated.sessions.length) },
    { role: "user", content: userPrompt(validated) },
  ];

  return await deps.llm.generateObject({
    schema: MetaReportAgentOutputSchema,
    messages,
    model: "doubao-seed-1-6-250615",
  });
}

### 6.2 `triggerMetaReport(request)` 完整伪代码(同步)

```ts
// src/api/metaReports.ts
import { v7 as uuidv7 } from "uuid";   // 新增依赖检查 §6.4
import { db } from "@/services/db";
import { runMetaReportAgent } from "@/core/agents/meta_report";
import { llm } from "@/core/llm";
import type {
  TriggerMetaReportRequest, TriggerMetaReportResponse,
  MetaReportDetailResponse, MetaReportListResponse, MetaReportListItem,
  MetaReportStatus,
} from "@eatit/shared-types";

const USER_ID = "local";  // §6.2 v3.4 单用户

export const triggerMetaReport = async (
  request: TriggerMetaReportRequest = {},
): Promise<TriggerMetaReportResponse> => {
  // 1) Aggregate eligible sessions (interview_reports.status='ready', JOIN interview_sessions).
  const filterIds = request.session_ids ?? null;
  const sessions = await loadEligibleSessions(filterIds);
  if (sessions.length === 0) {
    throw new Error("至少需要 1 场已完成的面试");
  }

  // 2) INSERT meta_reports row with status='generating'.
  const metaReportId = uuidv7();  // 与 Swift mainline UUIDv7 一致
  const createdAt = new Date().toISOString();
  const coveredSessionIds = sessions.map((s) => s.session_id);
  await db.exec(
    `INSERT INTO meta_reports (id, user_id, covered_session_ids, status, payload, created_at, updated_at)
     VALUES (?, ?, ?, 'generating', NULL, ?, ?)`,
    [metaReportId, USER_ID, JSON.stringify(coveredSessionIds), createdAt, createdAt],
  );

  // 3) Run agent inline (~30-60s for 1-10 sessions). Capture LLM error → mark failed.
  let payloadJson: string;
  let finalStatus: MetaReportStatus;
  try {
    const output = await runMetaReportAgent({ sessions }, { llm });
    payloadJson = JSON.stringify(output);
    finalStatus = "ready";
  } catch (err) {
    payloadJson = JSON.stringify({ detail: `${(err as Error).name}: ${(err as Error).message}` });
    finalStatus = "failed";
  }

  // 4) UPDATE row to terminal status.
  const updatedAt = new Date().toISOString();
  await db.exec(
    `UPDATE meta_reports SET status = ?, payload = ?, updated_at = ? WHERE id = ?`,
    [finalStatus, payloadJson, updatedAt, metaReportId],
  );

  // 5) Return TriggerMetaReportResponse. task_id 字段保持兼容 — 同步路径无 task_queue,
  //    填 metaReportId 作 placeholder(consumer 不依赖该值;UI 用 status 作完成判定)。
  //    status 字段:同步语义 → "ready"|"failed";UI 已能区分。
  return {
    id: metaReportId,
    task_id: metaReportId,                  // backward-compat placeholder
    status: finalStatus,                    // 同步:'ready' | 'failed'(不再 'generating')
    covered_session_ids: coveredSessionIds,
    created_at: createdAt,
  };
};

async function loadEligibleSessions(
  filterSessionIds: string[] | null,
): Promise<MetaReportAgentSessionInput[]> {
  const baseSql = `
    SELECT s.id AS session_id, s.created_at AS session_created_at,
           s.config_snapshot AS config_snapshot_json,
           r.payload AS report_payload_json
      FROM interview_sessions s
      JOIN interview_reports r ON r.session_id = s.id
     WHERE s.user_id = ? AND r.status = 'ready'
  `;
  let sql = baseSql, params: DBValue[] = [USER_ID];
  if (filterSessionIds && filterSessionIds.length > 0) {
    const placeholders = filterSessionIds.map(() => "?").join(",");
    sql = `${baseSql} AND s.id IN (${placeholders})`;
    params = [...params, ...filterSessionIds];
  }
  sql += ` ORDER BY s.created_at ASC`;
  const rows = await db.query(sql, params);
  return rows.map((r) => ({
    session_id: r.session_id as string,
    session_created_at: r.session_created_at as string,
    config_snapshot_json: (r.config_snapshot_json as string) ?? "{}",
    report_payload_json: (r.report_payload_json as string) ?? "{}",
  }));
}
```

### 6.3 `getMetaReport(id)` / `getMetaReportList()` 伪代码

```ts
export const getMetaReport = async (
  metaReportId: string,
): Promise<MetaReportDetailResponse> => {
  const rows = await db.query(
    `SELECT id, user_id, covered_session_ids, status, payload, created_at, updated_at
       FROM meta_reports WHERE id = ? AND user_id = ?`,
    [metaReportId, USER_ID],
  );
  if (rows.length === 0) throw new Error(`meta report not found: ${metaReportId}`);
  const r = rows[0];
  // Python 在 status='generating' 时 raise 409;同步路径理论上不会有 generating(同步立即写终态),
  // 但兼容 — UI 拿到 status='generating' 视为"重试加载"语义,不抛 409。
  return {
    id: r.id as string,
    user_id: r.user_id as string,
    status: r.status as MetaReportStatus,
    covered_session_ids: JSON.parse(r.covered_session_ids as string),
    payload: r.payload != null ? JSON.parse(r.payload as string) : null,
    created_at: r.created_at as string,
    updated_at: r.updated_at as string,
  };
};

export const getMetaReportList = async (
  params: { page?: number; page_size?: number } = {},
): Promise<MetaReportListResponse> => {
  const page = params.page ?? 1;
  const pageSize = params.page_size ?? 20;
  const offset = (page - 1) * pageSize;

  const totalRows = await db.query(
    `SELECT COUNT(*) AS cnt FROM meta_reports WHERE user_id = ?`,
    [USER_ID],
  );
  const total = (totalRows[0]?.cnt as number) ?? 0;

  const rows = await db.query(
    `SELECT id, status, covered_session_ids, created_at
       FROM meta_reports WHERE user_id = ?
      ORDER BY created_at DESC LIMIT ? OFFSET ?`,
    [USER_ID, pageSize, offset],
  );

  const items: MetaReportListItem[] = rows.map((r) => {
    const ids = JSON.parse(r.covered_session_ids as string) as string[];
    return {
      id: r.id as string,
      status: r.status as MetaReportStatus,
      covered_session_ids: ids,
      session_count: ids.length,
      created_at: r.created_at as string,
    };
  });

  return { items, page, page_size: pageSize, total };
};
```

### 6.5 同步 vs 异步

**决策:同步**。

| 维度 | 异步(Python 原 task_queue) | 同步(本 PR4b.dev 选) |
|---|---|---|
| latency UX | trigger 立即返回 202;前端 polling | trigger 等待 30-60s,期间 loading state |
| 一致性 | task 跑挂了 row 留在 generating,死锁 | INSERT + UPDATE 在同一 promise,要么终态要么直接 throw |
| 复杂度 | 需 task_queue 抽象 + worker | 0 额外抽象 |
| PR3b2 generateReport pattern | 已选同步 | **保持一致** |
| Swift 资源 | 不需要 | 不需要 |
| Bridge 调用次数 | 多(每次 polling 一次 GET) | 少(1 trigger + 0 polling) |

→ **同步**,与 PR3b2 一致。前端调用 `triggerMetaReport()` 时显示 loading;返回时直接 `status='ready'|'failed'`,无须 polling `getMetaReport`(但 list 页 / 详情页仍可用)。

**注意 contract drift**:Python `triggerMetaReport` 返回 `status='generating'`(异步);TS 同步返回 `status='ready'|'failed'`。UI 已 mirror Python 假设(可能 polling)。**不破坏**(UI polling getMetaReport 立即拿到 ready,语义等价),但 `MetaReportPage.tsx` 若有 `status==='generating'` 分支需注意 — PR4b.dev 实施时 grep 一下消费方,如果 polling 逻辑存在,可保留(同步路径下分支不会进)。

### 6.6 错误处理

| 错误 | 处置 |
|---|---|
| `loadEligibleSessions` 返 0 行 | throw `"至少需要 1 场已完成的面试"`(与 Python detail 同) |
| `runMetaReportAgent` ZodError(input PII / output 不合格) | 写 `payload={detail}` + `status='failed'`,**不**再 throw;返回 `status='failed'` |
| `runMetaReportAgent` LLM 网络错误 / 超时 | 同上 — 写 failed |
| `db.exec` INSERT 失败(罕见) | 直接 throw(无 row 可 mark failed) |
| `getMetaReport` 找不到 | throw `"meta report not found: <id>"` |
