## 3. TurnState TS 接口

### 3.1 字段命名:snake_case

**决策**:沿用 Python snake_case(`turn_index` / `previous_summary` / `framework_json` / `recent_turns` / `remaining_minutes` / `next_question`)。理由:M3.2.* 全部 schema 已用 snake_case(`previous_summary` / `preserved_keywords` / `followup_hints` / `live_observation`);三端透传无需重命名层;`core/schemas/**` + `core/agents/**` 已对 ESLint `camelcase` 豁免。例外:`TurnGraphDeps`(`llm` / `logger`)与函数名(`turnAssessmentNode` / `runInterviewerAgent`)用 camelCase — 这些是运行时句柄,不是序列化数据。

### 3.2 接口定义(developer 在 `core/schemas/turns.ts` 增量添加)

```ts
export const TurnAssessmentSchema = z.object({
  summary: z.string(),
  strengths: z.array(z.string()).default([]),
  weaknesses: z.array(z.string()).default([]),
}).strict();

export const TurnAssessmentSnippetSchema = z.object({ summary: z.string() }).strict();

export const TurnRecordSchema = z.object({
  question: z.string(),
  answer: z.string(),
  assessment: TurnAssessmentSnippetSchema.nullable().optional(),
}).strict();

export const InterviewerAgentInputSchema = z.object({
  framework_json: z.string(),
  recent_turns: z.array(TurnRecordSchema),
  long_term_summary: z.string().nullable().optional(),
  remaining_minutes: z.number().int().nullable().optional(),
}).strict();

// followup_hints: empty (degraded) OR 2-3 items, each ≤ 8 chars (Python field_validator)
export const InterviewerAgentOutputSchema = z.object({
  question: z.string(),
  intent: z.string(),
  expected_depth: z.enum(["surface", "tactical", "strategic"]),
  followup_hint: z.string().nullable().optional(),     // legacy single hint
  should_end: z.boolean().default(false),
  followup_hints: z.array(z.string().max(8)).max(3)
    .refine(arr => arr.length === 0 || (arr.length >= 2 && arr.length <= 3),
      { message: "followup_hints must be empty or 2-3 items" })
    .default([]),
  live_observation: z.string().max(30).nullable().optional(),
}).strict();

export const TurnStateSchema = z.object({
  // inputs (set before invoke)
  turn_index: z.number().int().nonnegative(),
  question: z.string(),
  answer: z.string(),
  framework_json: z.string(),
  recent_turns: z.array(TurnRecordSchema).default([]),
  previous_summary: z.string().nullable().optional(),
  remaining_minutes: z.number().int().nullable().optional(),
  // outputs (null until node populates)
  assessment: TurnAssessmentSchema.nullable().optional(),
  compressed: CompressionAgentOutputSchema.nullable().optional(),
  next_question: InterviewerAgentOutputSchema.nullable().optional(),
}).strict();
export type TurnState = z.infer<typeof TurnStateSchema>;
// 其余 type 别名同上,z.infer 一一对应。
```

`null` vs `undefined`:Python `None` → TS `null`。`state.assessment === null` 是"未运行"明确信号(对齐 Python state.py 设计意图)。

## 4. Channel reducers

LangGraph.js 0.2.74 的 `channels` API:每字段 `{ reducer: (left, right) => merged, default: () => initial }`(等价旧名 `value:`,已 `@deprecated` 但仍可用;developer **首选 `reducer:`**)。

**安全性论证**:并行写字段**互不重叠**:`turn_assessment` 只写 `assessment`、`compression` 只写 `compressed`、`next_question` 只写 `next_question`。所以 `(l, r) => r ?? l` 在 super-step 合并 partial updates 时绝不会丢任何分支输出。

| Field | Reducer | Default | Notes |
|-------|---------|---------|-------|
| `turn_index` | `(l, r) => r ?? l` | `() => 0` | input-only |
| `question` / `answer` / `framework_json` | `(l, r) => r ?? l` | `() => ""` | input-only |
| `recent_turns` | `(l, r) => r ?? l` | `() => []` | input-only,turn_graph 一次 invoke 不累加 |
| `previous_summary` / `remaining_minutes` | `(l, r) => r ?? l` | `() => null` | input-only |
| `assessment` | `(l, r) => r ?? l` | `() => null` | turn_assessment 写 |
| `compressed` | `(l, r) => r ?? l` | `() => null` | compression 写 |
| `next_question` | `(l, r) => r ?? l` | `() => null` | next_question 写 |

```ts
const channels: StateGraphArgs<TurnState>["channels"] = {
  turn_index:        { reducer: (l, r) => r ?? l, default: () => 0 },
  question:          { reducer: (l, r) => r ?? l, default: () => "" },
  answer:            { reducer: (l, r) => r ?? l, default: () => "" },
  framework_json:    { reducer: (l, r) => r ?? l, default: () => "" },
  recent_turns:      { reducer: (l, r) => r ?? l, default: () => [] },
  previous_summary:  { reducer: (l, r) => r ?? l, default: () => null },
  remaining_minutes: { reducer: (l, r) => r ?? l, default: () => null },
  assessment:        { reducer: (l, r) => r ?? l, default: () => null },
  compressed:        { reducer: (l, r) => r ?? l, default: () => null },
  next_question:     { reducer: (l, r) => r ?? l, default: () => null },
};
```

reducer 的 `right` 形参类型是 `T | undefined`(节点不返回该字段时是 `undefined`),`r ?? l` 正确处理"节点没写 → 保留 left"。

### 5.1 turnAssessmentNode(inline-Instructor,无独立 agent 模块)

const TURN_ASSESSMENT_SYSTEM =

### 5.2 compressionNode(委托 runCompressionAgent)

```ts
async function compressionNode(state: TurnState, deps: TurnGraphDeps): Promise<Partial<TurnState>> {
  const turns: CompressionTurn[] = [
    ...state.recent_turns.map(t => ({ question: t.question, answer: t.answer })),
    { question: state.question, answer: state.answer },
  ];
  const compressed = await runCompressionAgent(
    { previous_summary: state.previous_summary ?? null, turns },
    { llm: deps.llm, logger: deps.logger },
  );
  return { compressed };
}
```

约束:`runCompressionAgent` 已含 3s timeout + degradedSummary fallback,**不要二次 wrap timeout**。`CompressionTurnSchema.strict()` 只允许 `{question, answer}`,不能塞 assessment(那是 `TurnRecord` 的事)。

### 5.3 nextQuestionNode(汇合 + Interviewer + budget guard)

```ts
async function nextQuestionNode(state: TurnState, deps: TurnGraphDeps): Promise<Partial<TurnState>> {
  const currentTurn: TurnRecord = {
    question: state.question,
    answer: state.answer,
    assessment: state.assessment ? { summary: state.assessment.summary } : null,
  };
  const long_term_summary = state.compressed?.summary ?? state.previous_summary ?? null;

  let next_q = await runInterviewerAgent({
    framework_json: state.framework_json,
    recent_turns: [...state.recent_turns, currentTurn],
    long_term_summary,
    remaining_minutes: state.remaining_minutes ?? null,
  }, { llm: deps.llm });

  // Budget guard(对齐 Python turn_graph.py line 184-194)
  const budget = totalQuestionBudget(state.framework_json);
  if (budget !== undefined && !next_q.should_end && state.turn_index + 1 >= budget) {
    deps.logger?.info?.("interviewer.budget_guard", {
      answered: state.turn_index + 1, budget, forced_should_end: true,
    });
    next_q = { ...next_q, should_end: true };
  }
  return { next_question: next_q };
}
```

### 5.4 totalQuestionBudget helper

逐行翻译 Python `_total_question_budget`(`turn_graph.py` line 47-98)。签名:

```ts
function totalQuestionBudget(framework_json: string): number | undefined;
```

语义(developer 严格按 Python 实现):
1. `JSON.parse` 失败或非 object → return `undefined`。
2. **Shape 1 — legacy DirectionFramework**:`framework.stages: [{ question_budget: int, ... }]`。遍历 stages,累加每项的 `question_budget`(仅当 `Number.isInteger(b) && b > 0`);若 `total > 0` return total。
3. **Shape 2 — v3.2 FrameworkAgentOutput**:`framework.pace_plan.segments: [{ rough_minutes: int }]`。遍历 segments,累加 `Math.max(1, Math.floor(rough_minutes / 3))`(仅当 rough_minutes 是正整数);若 `total > 0` return total。
4. 否则 return `undefined`(让调用方 fall through 到 LLM 自己的 `should_end`)。

测试 fixture(M3.3.1.dev.b 单测必含):
1. legacy stages → return sum
2. pace_plan segments(rough_minutes=3 → 1, =10 → 3, =2 → 1)→ return sum
3. 非法 JSON / non-object / 空 stages 与空 segments / 全部非正整数 → return `undefined`
4. budget=N,turn_index=N-1(已答 N 次)→ 触发 force should_end=true 并打 log

## 6. 并行边(fan-out / fan-in)

### 6.1 拓扑(对齐 Python turn_graph.py line 11-13)

```
START ──► turn_assessment ──┐
   │                        ├──► next_question ──► END
   └──► compression ────────┘
```

节点名集合 `{ "turn_assessment", "compression", "next_question" }`(L0 锁第二次出现)。

### 6.2 边定义

```ts
graph
  .addNode("turn_assessment", (s) => turnAssessmentNode(s, deps))
  .addNode("compression",     (s) => compressionNode(s, deps))
  .addNode("next_question",   (s) => nextQuestionNode(s, deps))
  .addEdge(START, "turn_assessment")
  .addEdge(START, "compression")
  .addEdge("turn_assessment", "next_question")
  .addEdge("compression",     "next_question")
  .addEdge("next_question", END)
  .compile();
```

5 条边,顺序与 Python `turn_graph.py` line 201-205 完全一致。

### 6.3 Fan-in barrier 语义

LangGraph.js 0.2.74 Pregel 执行模型:**带多条入边的节点等所有上游 super-step 完成后才执行一次**,与 Python LangGraph 一致 → 端口保留因果性。依据(已查 `node_modules/.../@langchain/langgraph/dist/graph/{graph,state}.d.ts`):`StateGraph` 编译为 `Pregel`,`addEdge` 注册的多条入边由 Pregel runtime 在 super-step 末尾对齐 channel updates,在下一 super-step 触发下游节点一次。M3.1.3 smoke 已验证基本 super-step,§8.3 parallel test 进一步验证 fan-in。

### 6.4 并行依赖契约

- `turnAssessmentNode` 只读 `state.question` / `state.answer`(纯 input)
- `compressionNode` 只读 `state.previous_summary` / `state.recent_turns` / `state.question` / `state.answer`(纯 input)
- 两分支**不读对方输出**(turnAssessment 不读 compressed;compression 不读 assessment)→ 真正并行
- `nextQuestionNode` 既读 `state.assessment` 又读 `state.compressed` → 必须等两条上游 commit 后跑;Pregel barrier 自动处理
