## 1. 决策 — 核心结论

### 1.1 GO / NO-GO

**结论:NO-GO for bulk delete in a single M5.4.dev loop。必须 STAGED。**

物理 `rm -rf apps/api/` 现在执行 = JS 应用立即损坏(8 个 axios 模块 + 1 个 WebSocket 流尚在指向 FastAPI)。但**真正阻塞的不是 axios callsites**,它们是 application-layer fix;**真正阻塞的是 Swift 端 `Migrations.swift` 是空的**(13 行,只有 spec 注释,`MIGRATIONS: [...] = []`)— Bridge 那侧根本没 schema 可写入。换句话说:今天就算把所有 axios 指向 `db.exec/db.query`,也写不进任何表(没有表)。

故本节点裁定 M5.4.dev 必须拆分为 4 个有序子节点:

- **M5.4.dev.a** — 补 Swift `Migrations.swift` schema(由 Python alembic 7 个 mainline 迁移 → GRDB SQL 字符串 7 条逐条移植);**Swift 改动 + 测试**。这是 prerequisite,缺它前面 axios 替换无处落地。
- **M5.4.dev.b** — TS axios callsites 切到 `db.*` Bridge(8 个 `src/api/*.ts` 模块 + 2 个 `src/api/hooks/*` + 6 个 page consumers + 1 个 OfflineBanner)。
- **M5.4.dev.c** — InterviewPage WebSocket → TS `runInterviewSession` AsyncGenerator(architectural refactor,跨节点)。
- **M5.4.dev.d** — `rm -rf apps/api/` + workspace 清理 + dev 脚本剪枝 + Playwright `mockFullHappyPath` adapt/remove。

### 1.2 推荐序列(简版)

```
M5.4.dev.a  Swift Migrations + bridge db CRUD methods
   ↓
M5.4.dev.b  TS axios → Bridge sweep(8 模块,~600 LOC,逐 PR)
   ↓
M5.4.dev.c  InterviewPage WS → AsyncGenerator(architectural,~600-1000 LOC)
   ↓
M5.4.dev.d  rm -rf apps/api/ + workspace cleanup
```

详细序列、每步验收门、估算 LOC、Bridge method 新增清单见 §9。

### 1.3 spec drift — pyproject.toml 与 uv.lock 实际位置

M5.4.dev spec(行 2244-2260)叙述把 `pyproject.toml` / `uv.lock` 视作 root-level。**实际在 `apps/api/pyproject.toml` + `apps/api/uv.lock`**。仓库根 `package.json` 中只有一条 `"dev:api": "cd apps/api && uv run uvicorn ..."` script。无根级 Python 文件。`pnpm-workspace.yaml` 仅列 `apps/* / packages/*`,**自动包含 `apps/api`**(虽然它没有 `package.json`,pnpm 会对无 package.json 的 dir 静默跳过,所以没有 workspace 错误);删除时不需要修改 pnpm-workspace.yaml。

后续节点引用:本节点正式将"root pyproject.toml"理解修正为"`apps/api/pyproject.toml`"。M5.4.dev.d 删除范围 = `apps/api/` 整目录 + `package.json` 中 `dev:api` script 一行。
