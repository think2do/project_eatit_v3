### 1.1 Sequential not parallel — 关键决策

intake_graph 是**严格顺序**(parse → research → predict),**不是** turn_graph 的 fan-out / fan-in。

理由(逐字翻译 Python `intake_graph.py` line 10-25 的 M2.3.X audit-fix rationale):

> Research / Predict need company + role + industry-hint signals out of the JD. Pre-audit we tried to extract these via a regex hand-rolled inside the assets domain service, which silently always returned None — so research_node never had a real input and the Research Agent was never actually called in production. Parse Agent already reads the JD end-to-end; we now ask it to emit `jd_company_name / jd_role_title / jd_industry_hints` alongside the rest of its output. research_node consumes `state.parse_payload.jd_*` to construct its own input, which forces this to be sequential — research_node MUST run after parse_node has committed parse_payload.
>
> Trade-off: total parse-trigger latency rises ~30% (parse 8-15s + research 5-10s = 13-25s vs. the old "parallel but broken" 8-15s). We accept this because correctness > performance.

dev.c 在 `intakeGraph.ts` 注释里**逐字保留**这段 rationale,以阻止后续 reviewer 误把 intake_graph 改回 fan-out 形态。

### 2.4 15s research timeout(对齐 Python `RESEARCH_TIMEOUT_SECONDS = 15.0`)

`runResearchAgent` 内部**不需要**自己的 timeout(单次 LLM 调用 + Instructor 重试,M3.1.2 已处理)。timeout 由 graph 层的 `researchNode` 包裹:

```
Promise.race([runResearchAgent(...), timeoutPromise(15000)])
+ AbortController + Symbol("research_timeout") 哨兵
```

模板照搬 M3.2.3 `compressionAgent.ts` line 64-91 的 3s timeout 模式(已经 ship,文件路径 `core/agents/compression/index.ts`)。timeout 命中 → soft-skip:`research_payload: null, research_skipped: true, research_error: "timeout"`。详见 §5.2。

### 2.5 Soft-skip 语义(Python lines 142-193)

`research_node` **soft**(永不阻塞下游 `predict_questions_node`):
- 用户未 opt-in(`research_opt_in: false`) → skip,reason="opt_out"
- Parse Agent 没抽出 company / role(`parse_payload.jd_company_name` 或 `jd_role_title` 为空)→ skip,reason="insufficient_jd_signal"
- Research call 超时 → skip,error="timeout"
- Research call LLMError(任意子类)→ skip,error=`error.constructor.name`(对齐 Python `type(exc).__name__`)

skip 时统一返回 `{ research_payload: null, research_skipped: true, research_error: ... }`(reason 取代 error 时 error=null,实际 fail 时 error=string)。

`predict_questions_node` **double-skip guard**:
- `framework_config === null` OR `parse_payload === null` → no-op,返回 `{ direction_framework: null }`
- Framework call LLMError → no-op,返回 `{ direction_framework: null }`(caller `SessionsService` 等价物有自己的 retry+fallback)

### 2.6 Channel-key vs node-name 冲突 — 本图非问题

LangGraph.js 0.2.74 禁止同一字符串既是 channel key 又是 node ID(M3.3.1.dev.b 实战教训:`turnGraph.ts` 把 `next_question` channel 改名为 `next_question_out`)。

**本图不冲突**:
| Node name | 写入的 channel keys | 是否同名? |
|-----------|---------------------|-----------|
| `parse_node` | `parse_payload` | 否 |
| `research_node` | `research_payload` / `research_skipped` / `research_error` | 否 |
| `predict_questions_node` | `direction_framework` | 否 |

→ dev.c 直接用 §3 字段名做 channel key,**不需要**任何 `_out` 后缀重命名。

## 4. Channel reducers

LangGraph.js 0.2.74 `channels` API:每字段 `{ reducer: (left, right) => merged, default: () => initial }`(等价旧名 `value:`,已 `@deprecated` 但仍可用;dev.c **首选 `reducer:`**,与 turn_graph 对齐)。

| Field | Reducer | Default | Notes |
|-------|---------|---------|-------|
| `resume_text` | `(l, r) => r ?? l` | `() => ""` | input-only |
| `jd_text` | `(l, r) => r ?? l` | `() => ""` | input-only |
| `research_opt_in` | `(l, r) => r ?? l` | `() => false` | input-only;**注意 boolean 时 `??` 行为**:`r=false ?? l = false`(只有 null/undefined 触发 fallback),所以"false"也能正确写入 |
| `research_input` | `(l, r) => r ?? l` | `() => null` | input-only;backward-compat 槽,生产 caller 留 null |
| `framework_config` | `(l, r) => r ?? l` | `() => null` | input-only;null ⇒ predict_questions_node no-op |

| `research_payload` | `(l, r) => r ?? l` | `() => null` | research_node 写 |
| `research_skipped` | `(l, r) => r ?? l` | `() => false` | research_node 写;同上 boolean `??` 注意 |

### 5.2 researchNode — soft-skip + 15s timeout

逐行对应 Python `intake_graph.py` line 142-193:

```ts
async function researchNode(
  state: IntakeState,
  deps: IntakeGraphDeps,
): Promise<Partial<IntakeState>> {
  // Step 1: pick research_input — backward-compat slot wins, else derive from parse_payload
  let research_input: ResearchAgentInput | null = state.research_input;
  if (research_input === null) {
    research_input = deriveResearchInputFromParse(state);
  }

  // Step 2: opt-out / no signal ⇒ soft skip
  if (research_input === null) {
    const reason = state.research_opt_in ? "insufficient_jd_signal" : "opt_out";
    deps.logger?.info?.("research_node_skipped", { reason });
    return {
      research_payload: null,
      research_skipped: true,
      research_error: null,
    };
  }

  // Step 3: race runResearchAgent vs 15s timeout (template from M3.2.3 compressionAgent.ts)
  const controller = new AbortController();
  const timeoutSentinel = Symbol("research_timeout");
  const timeoutPromise = new Promise<typeof timeoutSentinel>((resolve) => {
    setTimeout(() => {
      controller.abort();
      resolve(timeoutSentinel);
    }, RESEARCH_TIMEOUT_MS);
  });

  try {
    const result = await Promise.race([
      runResearchAgent(research_input, { llm: deps.llm }),
      timeoutPromise,
    ]);
    if (result === timeoutSentinel) {
      deps.logger?.info?.("research_node_timeout");
      return {
        research_payload: null,
        research_skipped: true,
        research_error: "timeout",
      };
    }
    return {
      research_payload: result,
      research_skipped: false,
      research_error: null,
    };
  } catch (err) {
    // LLMError or any thrown Error from runResearchAgent (incl. ZodError on schema rejection)
    const errorName = (err as Error)?.constructor?.name ?? "Error";
    deps.logger?.info?.("research_node_llm_error", { reason: errorName });
    return {
      research_payload: null,
      research_skipped: true,
      research_error: errorName,
    };
  }
}

export const RESEARCH_TIMEOUT_MS = 15_000;  // mirror Python RESEARCH_TIMEOUT_SECONDS = 15.0
```

**Logging key 锁**(L0 #11 审计需要):
- `research_node_skipped` + `{reason: "opt_out" | "insufficient_jd_signal"}`
- `research_node_timeout`
- `research_node_llm_error` + `{reason: errorClassName}`

dev.c 必须使用以上**精确字符串**(对齐 Python `intake_graph.py` line 159 / 173 / 181)。

### 5.3 deriveResearchInputFromParse — 逐行翻译 Python helper

逐行翻译 Python `_derive_research_input_from_parse`(`intake_graph.py` line 242-274)。

```ts
export function deriveResearchInputFromParse(
  state: IntakeState,
): ResearchAgentInput | null {
  if (!state.research_opt_in) return null;
  const payload = state.parse_payload;
  if (payload === null) return null;
  const company = (payload.jd_company_name ?? "").trim();
  const role = (payload.jd_role_title ?? "").trim();
  if (!company || !role) return null;
  let hints = (payload.jd_industry_hints ?? [])
    .map((h) => h.trim())
    .filter((h) => h.length > 0);
  if (hints.length === 0) hints = [role];
  // safeParse — schema rejection (e.g., trim resulted in empty company) → return null
  const result = ResearchAgentInputSchema.safeParse({
    company_name: company.slice(0, 80),
    role_title: role.slice(0, 80),
    industry_hints: hints.slice(0, 5),
  });
  return result.success ? result.data : null;
}
```

**Judgment call**:用 `safeParse` 而非 try/catch `parse` — 同义但更显式表达"schema 拒绝是预期分支"。Python 用 `try / except ValidationError` 等价。

```ts
import {
  ResearchAgentInputSchema, ResearchAgentOutputSchema,
  type ResearchAgentInput, type ResearchAgentOutput,
} from "@/core/schemas/research";
import type { LLMProvider } from "@/core/llm/types";

export interface ResearchAgentDeps { llm: LLMProvider; }

export async function runResearchAgent(
  input: ResearchAgentInput,
  deps: ResearchAgentDeps,
): Promise<ResearchAgentOutput> {
  // ★ Defense layer 1: Schema-level — .strict() rejects ANY unknown field BEFORE LLM call
  const validated = ResearchAgentInputSchema.parse(input);  // throws ZodError on PII

  // ★ Defense layer 3: cache_key derivation (sha256 truncated to 16 chars)
  const cacheKey = await computeCacheKey(validated);

  // ★ Defense layer 2: prompt explicitly states "input contains ONLY company/role/industry"
  const messages: Message[] = [
    { role: "system", content: systemPrompt() },
    { role: "user", content: userPrompt(validated) },
  ];

  // M3.1.2 LLMProvider.generateObject — Instructor retry on ZodError
  const llmResult = await deps.llm.generateObject({
    schema: ResearchSubObjectSchema,  // company + industry only (mirror Python _ResearchSubObject)
    messages,
    model: "doubao-seed-1-6-250615",
  });

  // Wrap LLM sub-output into final ResearchAgentOutput (add cache_key + fetched_at + degraded flags)
  return ResearchAgentOutputSchema.parse({
    company: llmResult.company,
    industry: llmResult.industry,
    fetched_at: new Date().toISOString(),
    cache_key: cacheKey,
    degraded: false,
    degraded_reason: null,
  });
}
```

**`ResearchSubObjectSchema`** — dev.b 在 `core/agents/research/index.ts` 内定义:对齐 Python `apps/api/app/agents/research/service.py` line 51-53,只含 `company: CompanyProfileSchema` + `industry: IndustryProfileSchema`(均已在 `core/schemas/research.ts` 存在)。理由:LLM 不应该自己生成 `cache_key` 和 `fetched_at` — agent layer 注入。

### 8.3 cache_key derivation — Web Crypto vs fnv1a 二选一

**Python**:`hashlib.sha256(f"{company}|{','.join(industry_hints)}".encode("utf-8")).hexdigest()[:16]`

**TS 选项**:

| 选项 | 优点 | 缺点 |
|------|------|------|
| **A. `crypto.subtle.digest('SHA-256', ...)`** | 与 Python 完全一致;Web 标准 | 异步(async/await);vitest + happy-dom 可能缺失 |
| **B. fnv1a 64-bit 同步** | 同步;无依赖 | 与 Python 不同 hash;cache 无法跨端复用 |
| **C. node:crypto `createHash`** | 同步;与 Python 一致 | macOS Electron renderer 不能 import `node:` 模块 |

**推荐方案:A(Web Crypto subtle)**,在 `runResearchAgent` 中 await,理由:
1. macOS App Store 端是 Electron 渲染层,Web Crypto 在 main / renderer / worker 三处都可用(M2.8.dev.e `crypto.randomUUID` 已有先例,见 `apps/desktop/src/services/asr.ts` line 247)
2. 与 Python 同 hash,cache 跨端兼容(虽然 §8.5 defer cache,但保留语义对称)
3. async helper 已经契合 `runResearchAgent` 的 `async` 形态

**测试环境**(vitest):happy-dom 默认**不**注入 `crypto.subtle`;dev.b 在 `apps/desktop/src/test/setup.ts`(若存在)或 test 文件 top-level 使用 `import { webcrypto } from "node:crypto"; globalThis.crypto = webcrypto as any;` polyfill。这是已知 vitest 模式,Vite 文档有记录。

```ts
async function computeCacheKey(input: ResearchAgentInput): Promise<string> {
  const raw = `${input.company_name}|${input.industry_hints.join(",")}`;
  const buf = await crypto.subtle.digest("SHA-256", new TextEncoder().encode(raw));
  return Array.from(new Uint8Array(buf))
    .map((b) => b.toString(16).padStart(2, "0"))
    .join("")
    .slice(0, 16);
}
```

**Unknown #1**(§11):dev.b 验证 happy-dom 是否需要 polyfill;若 polyfill 复杂度过高,dev.b 报告并切到方案 B(fnv1a),同步在 spec 备案 cache 不跨端兼容。

## 10. IntakeGraphDeps + buildIntakeGraph 工厂

  logger?: {
    info?(msg: string, meta?: Record<string, unknown>): void;

}

export function buildIntakeGraph(deps: IntakeGraphDeps) {
  const graph = new StateGraph<IntakeState>({ channels })
    .addNode("parse_node",             (s) => parseNode(s, deps))
    .addNode("research_node",          (s) => researchNode(s, deps))
