### M4 `.ralph/.last_output_length` 未 gitignore

虽然当前是 untracked 状态（不会污染 commit），但若被意外 `git add .` 则会进入仓库。

### M6 M1.3 TestFlight 链路 — 静态 OK，live upload 人工门控
`archive-and-upload.sh` 脚本静态正确（method=app-store / teamID=469QTH6TU2 / @keychain:AC_PASSWORD），但以下 5 步未完成，live upload 无法执行：

2. App Store Connect 创建 App ID `com.eatit.desktop` + Eatit App 记录
3. Apple Distribution 证书 .p12 导入本地 keychain
4. App-specific password 存入 keychain（`security add-generic-password -s AC_PASSWORD`）
5. `export APPLE_ID="<actual-apple-id>"` 并执行脚本
**建议处置**：这是 M1.3 已知 deferred 状态，已在 commit 758be58 注明"live upload human-gated"。不需要 audit-fix 节点，人工处理。

### M7 SWIFT_VERSION = "5.0" 与 Swift 6 编译器的语义
`project.yml` `SWIFT_VERSION: "5.0"` 表示以 Swift 5 语言模式编译，编译器实为 Swift 6.3.1（Xcode 26）。build 通过，功能正常，但 design doc §10.3 提到"Swift Strict Concurrency 默认级别"风险。`SWIFT_STRICT_CONCURRENCY: minimal` 已手动设置，规避了 Swift 6 严格并发升级。
长期来看，M2+ 引入 async/await 原生 Service 后应评估是否升级到 Swift 6 语言模式。
**建议处置**：不阻 M1，记录技术债，留待 M2.x 或 M6 pre-release 评估。
