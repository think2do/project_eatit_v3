## 3. 🟡 Minor — non-blocking

- **🟡 upload-to-config.spec.ts pre-existing strict mode violation**: `upload-to-config.spec.ts:32` 的 `getByText('结构化面试官', { exact: true })` 因 `SummarySidebar` 在 `/config` 路由下也渲染所选风格标签,导致 Playwright strict mode 报 "resolved to 2 elements"。这是 M4.3 SummarySidebar 增强引入的行为变化,但 **不是本 M4.X 审计节点引入的** — 该文件在 M4.X scope 外(我们不修改产品代码)。建议在 M5 初期以 `getByRole('button', { name: /结构化面试官/ })` 替换修复,或直接用 `.first()` — 属 1-line fix。记录为 🟡 non-blocking。

- **🟡 InterviewPage E2E 已降级为 route mount 验证,未做交互断言**: full-happy-path.spec.ts 对 `/interview/:sessionId` 仅 assert URL 匹配(不 crash),未验证 LiveCaption/ObserverPanel 渲染、语音控制可见等。原因:实际交互需要麦克风权限 + Volcengine SAUC 凭据,Playwright headless 环境无法满足。降级策略与 M3.4.X audit 保持一致,属已知设计限制。真实 ASR 链路由操作员手工回归(见下方 Manual E2E Playbook)。

- **🟡 Reflection 异步轮询在 E2E 中以静态 ready mock 代替**: MetaReportPage 实际走 1500ms 轮询循环(最长 180s 超时)。full-happy-path.spec.ts 通过 `mockFullHappyPath` 直接返回 `status: "ready"` 跳过了轮询等待。轮询逻辑的健壮性已在 M3.3.X 审计中静态审查;`POLL_TIMEOUT_MS = 180_000` + `cancelledRef` 清理路径完整。E2E 层面的真实轮询验证需要 live backend,标记为 operator 手工项。

- **🟡 mockApi 路由覆盖范围未集中**: full-happy-path.spec.ts 内联了独立的 `mockFullHappyPath()` 函数,与 `mockApi.ts` 的 `mockReportApi()`/`mockUploadFlow()` 存在部分重复(onboarding gate 桩、report 桩)。原因:task 边界要求"不修改产品代码,仅纯 mock setup 小量增加可接受"(选项 b — 限制覆盖范围 + 文档化 gap)。M5 阶段建议将所有 backend mock 合并到 `mockApi.ts` 的单一 `mockAllApis()` 工厂函数以减少重复。

- **🟡 report-renders.spec.ts 中 `/health` 端点 unhandled**: `[mockApi] unhandled backend call: http://127.0.0.1:8000/health` 在 report-renders.spec 运行期间打印两次。该调用来自某 useEffect 的健康检查,返回 404 后不影响报告页面渲染(report 页不依赖 /health 200 才显示内容)。但持续打印 warn 日志会干扰 CI 输出阅读。建议 M5 在 `mockReportApi()` 中补充 `/health` stub。
