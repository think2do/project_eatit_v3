## §4 🟡 minor 缺口 / known-deferred

**1. 🟡 (latent §B9 schema drift) ASRGateway.swift line 170 dispatches reason="abrupt"，JS ASREndPayloadSchema 不含此值**

`apps/macos/Eatit/Services/ASRGateway.swift:170` 在 `disconnect(graceful: false)` 路径下派发 `asr-end` with `{"reason": "abrupt"}`；而 `apps/desktop/src/services/asr.ts:61` 的 `ASREndPayloadSchema` 仅允许 `z.enum(["stop","client-stop","eof","1011","1006","error"])`，缺少 `"abrupt"`。若该路径触发，`ASREndPayloadSchema.parse()` 在 `asr.ts:186` 处会抛出 Zod 验证错误，导致 AsyncIterator 崩溃。

**当前风险评估**：`disconnect(graceful: false)` 在全部生产代码路径中从未被调用（`WebViewController.swift:374` 使用默认 `graceful=true`；`reconnectSilent` 不调用 disconnect；bridge handler `asr.stop` 也使用默认值）。此路径仅在 XCTestCase `testDisconnectAbrupt_NoLastFlagDispatchesAbruptEnd`（`ASRGatewayReceiveTests.swift:345`）中被测试。**当前不可在生产中触达，但 schema drift 存在，M3 引入新调用路径时存在激活风险。**

修复建议：将 `"abrupt"` 添加到 `ASREndPayloadSchema` 的 `reason` enum（同一 commit 中同时在 Swift / JS 两端固化），或将 Swift 端改为统一使用 `"eof"`。

**2. 🟡 (doc-drift) BridgeMessage.swift:103 comment 仅列 4 种事件类型，遗漏 stream-end / stream-error / file-dropped**

`apps/macos/Eatit/Bridge/BridgeMessage.swift:103-106` 注释写 `"stream-chunk" | "asr-partial" | "asr-final" | "asr-end"`，但 M2.7.dev.c 新增了 `stream-end` / `stream-error`，M2.4 新增了 `file-dropped`，实际 dispatch 路径（LLMGateway.swift + ASRGateway.swift + WebViewController.swift）共覆盖 7 种事件类型。注释未随代码更新，无功能影响，属纯文档漂移。

**3. 🟡 (known-deferred) XCTest runner env-block：102 个 XCTest case build 通过但无法 run**

`xcodebuild test` 报告 "test runner hung before establishing connection"，与 M1.X audit 相同的 provisioning/signing env-block（无 Apple Dev Portal provisioning profile，本地 run 无法启动 macOS app sandbox 下的 test runner）。`xcodebuild build-for-testing` 返回 TEST BUILD SUCCEEDED，代码本身正确。**CI 环境（有正确 provisioning）应能跑通；不触发 audit-fix。**

实际 XCTest 覆盖矩阵：BridgeRouterTests(7) / KeychainServiceTests(7) / DatabaseServiceTests(6) / FilePickerServiceTests(4) / PDFParserServiceTests(5) / AudioCaptureServiceTests(7) / LLMTypesTests(16) / LLMGatewayTests(11) / ASRGatewayFrameTests(17) / ASRGatewayConnectTests(9) / ASRGatewayReceiveTests(13) = **102 cases**。Protocol seam 注入设计确保每个 service 有 mock-based 单元测试，满足 §F 80% 行覆盖率意图（行覆盖率数值需 CI 运行后确认）。

**4. 🟡 (needs-manual-action) ARK 真调 + SAUC 真调 manual gate 尚未执行**

d824edf（M2.7.dev.d）commit body 含完整 ARK manual real-call checklist（5 步，需用户填入 ark-api-key 到 Keychain 后手动执行）。e544eb9（M2.8.dev.e）commit body 含完整 SAUC manual real-call checklist（7 步，需 volc-asr-credentials JSON 写入 Keychain 后手动执行）。architect §11.2 Phase 5 / §10.7 显式标注这两个 gate 为 "manual / acceptance video，不进自动测试"。**目前均为 unchecked 状态；用户应尽早执行，以发现协议帧格式 / 4-header 名值 / SSE 解析 mismatch。不触发 audit-fix。**

**5. 🟡 (known-deferred) Volcengine SAUC 16 项推断字段未经官方文档校验**

M2.8.arch 设计中 ASR binary frame 格式（packFirstFrame / packAudioFrame）基于 architect 三次 WebFetch 全空白后的推断。mock URLSessionWebSocketTask 覆盖了接收循环逻辑，但 binary frame 字节布局 / 4 个 header 名值（X-Api-App-Key / X-Api-Access-Key / X-Api-Resource-Id / X-Api-Connect-Id）的正确性将在 manual real-call gate（M2.8.dev.e）首次校验。**pre-M2 风险，architect §13 已显式注明；不触发 audit-fix。**

**8. 🟡 (benign asymmetry) JS ASREndPayloadSchema 包含 "eof" 和 "1006" 但 Swift 从未 dispatch**

`asr.ts:62` enum 含 `"eof"`（Swift 无对应 dispatch，`"stop"` 用于 normalClosure）和 `"1006"`（Swift 对 abnormalClosure 路径经重试后 dispatch `"error"` 而非 `"1006"`）。这属于 JS 端 additive schema（预留 future reason 值），不破坏任何现有路径。Zod `z.enum` 的 parse 行为是拒绝不在 enum 内的值，而 `"eof"/"1006"` 在 enum 内、只是 Swift 不发送，parse 层面无问题。**无需修复。**
