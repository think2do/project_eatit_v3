## 3. 🟡 Minor(Non-blocking) — nice-to-have

- **🟡 实时性能门禁(首字 < 800ms / 松手 < 1.5s)未在此审计环境实测**: 本节点 Ralph 子 agent 无真实麦克风、无 Volcengine SAUC 凭据、无 Xcode 真机构建能力。1500ms timeout unit test(volcStreamAsr.test.ts case 7)作为上界合同代理:证明若 Swift drain + Volc final 在 1.5s 内未到达,volcStreamAsr 保证 reject — 这是 back-stop 而非 latency 测量。真实延迟需操作员在 Mac 上人工回归(见下方 Manual E2E Test Plan)。记录为 🟡 non-blocking:本节点分工明确排除了无凭据环境下的真实链路测试。

- **🟡 LiveCaption 使用内联 style 而非设计 token**: `LiveCaption.tsx` 内联 style 对象中 `padding: "10px 14px"` / `fontSize: 14` / `lineHeight: 1.6` 等数值为硬编码,仅部分使用 `var(--r-md)` / `var(--line)` / `var(--bg-sunken)` 等 CSS 自定义属性。组件头注释已标注"Classes are placeholder Tailwind-style names pending M5 design-token audit follow-up"。M5 设计 token 审计前可接受;记录在此以提醒 M5 阶段统一替换。

- **🟡 pulse 动画使用 `animation: "pulse 1.2s..."` 内联但无 @keyframes 注入**: LiveCaption.tsx:64 的脉冲小圆点引用 `animation: "pulse 1.2s ease-in-out infinite"`,但 `@keyframes pulse` 需在全局 CSS 中定义。若全局 CSS 未定义该关键帧,小圆点显示为静止(无动画),功能不损坏,视觉略有差异。已查看 liveCaptionFlow.test.tsx — 测试在 jsdom 中运行,不涉及 CSS 动画执行,因此测试通过不代表动画有效。需在视觉验收环节人工确认。

- **🟡 handleVoiceStop 的 endCapture 调用使用可选链(`?.`),若 controllerRef.current 为 null 则静默跳过**: InterviewPage.tsx:432 为 `await controllerRef.current?.endCapture()`。mount useEffect 保证 controller 在组件生命周期内非 null,但极端 race(组件 unmount 与 handleVoiceStop 并发)可能导致 result 为 undefined,此时 `TRANSCRIPT_FINAL` 未 dispatch 但 `AUDIO_STOP` 仍在 finally 中触发(line 439)。当前逻辑在 line 433 已有 `if (result)` 保护,行为安全;但潜在的"用户说完话、transcript 丢失"UX 问题值得在 M4 稳定化后补充 null-controller 日志或 fallback 提示。

### Manual E2E Test Plan (M3.4.X gate — operator runs on Mac with real credentials)

**前提条件**: macOS 14.4+,Xcode 15.4+,Volcengine SAUC 凭据已存入 macOS Keychain(`volc-asr-credentials` item,含 appid / token / cluster)。

**Step 1 — 构建与启动**
在 Terminal 执行:
```
cd /Users/shixuan/project_eatit_v3/eatit
open apps/macos/eatit.xcodeproj
```
在 Xcode 中选择 target `eatit (macOS)`,确认 Signing 使用开发者账号(不需要 App Store entitlements,开发 build 即可),点击 Run(⌘R)启动。

**Step 2 — 进入面试页面**
在 App 内完成候选人信息配置(JD + 简历)→ 进入面试会话页面。确认左下角显示"麦克风"或"语音"模式,且未显示 ASR 不可用的警告 banner。

**Step 3 — 按住空格开始录音**
按住 Space 键。计时器 T0 = 按下时刻。观察 LiveCaption 区域(输入框下方)出现"正在聆听..."脉冲指示器。

**Step 4 — 朗读测试语句并计时首字**
保持按住 Space,以正常语速朗读:"你好世界,这是一次流式 ASR 性能测试。"(约 3-4 秒)。
- 当 LiveCaption 区域从"正在聆听..."变为首个中文字符(如"你")时,记录时间 T1。
- 计算 **首字延迟 = T1 - T0**,目标:< 800ms。
- 继续朗读观察 LiveCaption 实时刷新(替换语义,非追加)。

**Step 5 — 松手并计时 final 落屏**
讲完后松开 Space 键。计时器 T2 = 松开时刻。
- 观察 LiveCaption 区域从斜体灰色 partial 文字切换为正体黑色 final 文字(role="status" 消失,`<p>` 出现)。
- 记录 T3 = final 文字出现时刻。
- 计算 **松手→final 延迟 = T3 - T2**,目标:< 1.5s。

**Step 6 — 验证 final 进入 turn_graph**
final 出现后约 1-3 秒,InterviewPage 应开始显示 AI 下一问题生成中的状态(Interviewer Agent 输出)。
- 确认新问题成功出现(Compression Agent + Interviewer Agent 均处理了本轮答案)。
- 在 Xcode Console 中搜索 `[ASR]` 或 `streamId` 日志,确认无 `asr.no-final-received` 错误。

**Step 7 — 验证关闭后无泄漏**
退出面试页面(navigate back 或关闭窗口)。
- 在 Xcode Console 确认无 `Swift task cancelled` 异常或 `WebSocket connection leak` 警告。
- 在 App 内重新进入面试页面,再次按住空格,确认新的 ASR stream 正常启动(controller 重新创建,旧 abort 不影响新实例)。
